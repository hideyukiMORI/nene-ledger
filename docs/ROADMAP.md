# ロードマップ — NeNe Ledger

> Status: normative（規範）/ 2026-10-22 初版（Issue #5・公開前の番号。[ADR 0021](adr/0021-public-repository-on-github.md)）/ 2026-11-05 M2〜M4 を組み替え（GitHub Issue #8・業務ペルソナ 5 人の洗い出し）
> 何を作るかは [FEATURES.md](FEATURES.md)、なぜかは [ADR](adr/README.md)。ここは**どの順で、何をまとめて、何をもって終わりとするか**だけを決める。
> 🔴 **期日は書かない。** 見積もりの根拠がまだ無い。順番と終わりの条件だけを約束する。

## 0. 読み方

- マイルストーン（M）は、利用者に見せられる 1 つのまとまり。前の M が終わってから次へ進む（並べてよいのは、前の M の終わりに関係しない準備だけ）
- **終わりの条件**は、含む機能が FEATURES.md ですべて `確認済み` になり、M ごとに決めた実測と実機の確認の記録があること
- 🔴 **Windows の実機で確かめるまで、M1 以降は終わらない**（QLT-013・ADR 0002）
- 🔴 **2026-10-22 時点で、Windows の exe を組み立てて実機で動かす経路は保留**（Issue #7。開発機で試験用の exe が検疫された）。施主の判断で、当面 exe を組み立てずに進める。Windows のコードは `make lint-windows`（型検査だけで exe を作らない）で見続け、実機の確認は経路が決まってからまとめて行う
- 機能は FEATURES.md の番号で書く。フェーズ 1 の 120 項目は M1〜M4 に全部入る
- 🔴 **2026-11-05 の組み替え（GitHub Issue #8）**: 業務ペルソナ 5 人（経理・EC・アナリスト・ETL・人事名簿）の票で、検索・置換・Undo は「編集と同じ版」に要ると分かった。検索と壊れた行の手直しを M2 に集めた。計算パレット（STAT-09）は 0.1.0 に入れる
