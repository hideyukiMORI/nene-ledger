# ADR 0003 — 差分に必要な検証と成功結果の再利用

- 状態: 受理
- 日付: 2026-10-22
- Issue: #1
- 根拠: NeNe Nib で施主が 2026-09-20 に示した方針（Nib ADR 0021）と、NeNeDocket ADR 0003 の継承
- 影響する規則: QLT-001 / QLT-002 / QLT-007 / QLT-008 / QLT-009 / QLT-010 / QLT-012 / GIT-004

## 決定

1. 完了条件は、差分の挙動と直接の依存・呼び出し元で起こり得る退行を検出する最小限の検証と、その記録・レビュー。各テストの必要性を説明できなければ実行しない。`make` の個別 target と `cargo test -p <crate> <name>` を使う
2. 検証済みの実装・テスト・関連依存・必要な環境条件が不変なら、担当・工程・文書・コミット SHA が変わっても成功結果を再利用する。統合記録に対象、退行の根拠、コマンドと結果、記録の場所、再利用元と不変性の根拠を書く
3. `make check` の全件検証は `REASON=<限定できない理由>` の明示指定でのみ実行する。指定なし・空の理由は実行前に拒否する
4. 統合の前の `make ci` は Git 規約、統合記録の存在、差分の空白を確認する。製品テストは重ねて走らせない。記録の妥当性と入力の不変性はレビューで確認する（リモートも CI も無い・ADR 0004）
5. 差分が原因の失敗は修正する。無関係な既存失敗は根拠と別 Issue を記録して本件を継続する。成功するまでの反復で不安定さを隠すことを禁止する
6. 文書・コメント・規約だけならアプリの動作検証は不要。フック・開発ツールは変更した道具の正例・反例を短く確認する。coverage・`make prove` も関連する変更時に選ぶ
7. **セルの切り出し・並べ替え・集計・保存に触れた変更は、QLT-008 の 3 つ（速い経路と参照実装の一致・切り方の不変・触っていない行のバイト一致）のうち該当するものを必ず回す。** これは「差分に必要な検証」の最小に含まれる

## 強制

- **planned**: `make check` の `REASON` 要求、`make ci` の欄の検査、文書整合。Issue #2 で `Makefile` と `xtask` を置き、実測してから active にする

## 既存決定との関係

NeNeDocket ADR 0003 を継承し、CI の必須 check を「統合の前の `make ci`」に置き換えた。検査の判定基準は変えない。

## 検証

本 ADR 自体は文書なので、アプリのビルド・動作は無い。Issue #1 では相対リンクと規則 ID の定義を grep で確かめた（gate-proofs 第 2 節）。

## 却下

- 全件テストを毎回繰り返す: 不変の入力を工程だけで測り直す
- 大規模な自動選定・キャッシュ基盤: この規模を超える
- 全検査を無効化する: 必要な退行確認と Git・統合記録の確認を失う
- QLT-008 の 3 つを「関連するときだけ」にする: それらはこの製品の約束（FR-003）そのものであり、切り出し・並べ替え・保存の変更は常に関連する
