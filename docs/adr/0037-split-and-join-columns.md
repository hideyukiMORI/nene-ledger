# ADR 0037 — 列の分割と結合は、元の列を残して右に新しい列を足し、1 手で戻す

- 状態: 受理
- 日付: 2026-11-16（受理 2026-11-16）
- Issue: #517（GitHub）
- 影響する規則: FR-003 / FR-005 / FR-011 / ARC-001 / ARC-011 / EDIT-03・08 / UNDO-01 / ADR 0024 / ADR 0027 / ADR 0029 / ADR 0031

## 文脈

EDIT-08（列の結合と分割・区切り／正規表現／固定幅）は M2 に残る編集の最後の大きな項目で、競合の多くが持つ（Excel の「区切り位置」・OpenRefine・EmEditor）。

Excel の「区切り位置」は、分けた値を**元の列と右隣の列に上書き**する（右に値があれば「置き換えますか」と尋ねる）。元の値は残らない。本製品の約束（FR-003「勝手に変えない」）と、今ある列の操作の作りに合わせて決める必要がある。

今の土台（コードで確かめた）は次のとおり。

- 列を足すことと、足した列のセルに値を書くことを 1 手に束ねる道がある（`EditHistory::record_batch`）。列の複製（GitHub Issue #488）がこの道で、全部の行を合成ルートが読んで `Document` に渡す
- 差分はセルごとに持つので、記憶は書いたセルの数に比例する（100 万セルで約 650 MB・benchmarks 第 7 節）。列の複製は 10 万行までに限っている
- 正規表現は core にある（`regex-automata`・ADR 0031）。検索の欄の条件（大文字小文字・正規表現）の札もある

## 決定

**分割も結合も、元の列には触らず、すぐ右に新しい列を足して値を書く。列を足すことと値を書くことは 1 手で、Ctrl+Z 1 回で戻る。**

1. **分割**：パレットの「列を分割する…」。カーソルの列（列全体を選んでいれば、その 1 列）を分ける。段の欄に区切りを打つ。
   - 文字どおりの区切り（`-`・空白・`／` など。1 字でも数字でもよい）
   - 正規表現（検索の欄と同じ「正規表現」の札）
   - 固定幅（札で「幅」に替え、`3,5,2` のように字の数を打つ。全角も 1 字と数える）
   - 分ける数の上限（欄の後ろに `、3` と打てば、3 つ目に残りを全部入れる）は初めは入れない
2. **段の中で先に見せる**：打つたびに、見えている行の分け方を下に並べる（読み方の選び直しの「試す」と同じ）。足す列の数は、全部の行の中で最も多く分かれた数（上限 64 列）。
3. **足す列の名前**：見出しがあれば `元の名前 1`・`元の名前 2`…。見出しの行は分けない。
4. **結合**：パレットの「列を結合する…」。選んだ 2 つ以上の続いた列を、左から順に、打った区切り（空でもよい）でつないだ値を、選んだ範囲のすぐ右の新しい 1 列に書く。「セルが無い」所は飛ばす（区切りも入れない）。空のセルは空の値としてつなぐ。名前は `左の名前 ＋ 右の名前`。
5. **元の列は残す**。要らなければ利用者が消す（Ctrl+-）。分けた値で元の列を置き換える操作は作らない。
6. **上限**：列の複製と同じ（全部の行を読む・10 万行まで・索引を作り終えてから）。超える表では断って理由を言う。
7. **保存**は今までの道（列を足した保存）。触っていない列のセルは、原本のバイト列から写す。

## 強制

- **planned**（受理の後の Issue で）:
  - 分割した列を同じ区切りで結合すると元の値に戻る（区切りが文字どおりのとき・乱数の表）
  - 分割・結合の後も、元の列のセルの書き換えは 0（差分に元の列が現れない）
  - Ctrl+Z 1 回で、足した列とその値が全部消える
- **不能（レビュー事項）**: 段の見え（先に見せる分け方）が、書く値と同じか

## 結果

- 得るもの：`姓 名`・`2026/11/16`・`東京都-千代田区` のような列を、元を失わずに分けられる。1 手で戻せる。
- 失うもの：Excel の「区切り位置」と違い、元の列が残る（消す 1 手が要る）。10 万行を超える表では使えない。
- 残る穴：10 万行の上限は、差分をセルごとに持つ作りから来る。超える表で要るなら、差分に「列にかける規則」を持たせる（XFRM-01・M4 の変換の規則）ほうが筋がよい。そのときは、分割も結合も規則の 1 種として持ち直す。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| Excel と同じく、元の列と右の列に上書きする | 元の値が消える。右の列の値を巻き込む。尋ねる画面で防ぐより、初めから壊さない |
| 分けた値で元の列を置き換え、余りを右に足す | 元の値が消える（Ctrl+Z でしか戻らない）。保存してしまえば戻せない |
| 初めから「列にかける規則」（XFRM-01）として作る | 規則の層（表示で計算し保存で反映）はまだ無く、M4 の設計。M2 のうちに使える形を先に出し、規則の層ができたら持ち直す |
| キーを割り当てる | 毎日の操作ではない。パレットで足りる（行と列の複製と同じ判断） |

## 施主の判断（2026-11-16・GitHub Issue #545）

施主は、下の問いのすべてを**推しのとおり**とし、受理した（「推しで受理・マージ」）。実装の後に実機で見て判断が変われば、新しい ADR か追記で直す。

### 尋ねたこと

1. **元の列は残す**でよいか（推し）。「分けた値で置き換える」を選べるようにするか
2. 固定幅は初めから要るか。区切りと正規表現だけ先に出して、固定幅は後でもよいか（推し：3 つとも初めから。段の札 1 つの違い）
3. 10 万行の上限のままでよいか（推し：M2 はこのまま。超える表は M4 の規則で）
