# ADR 0027 — 行と列の挿入と削除は Excel と同じ見え方と操作にする。行の番号は上から通し番号、消すときは尋ねずに Undo で戻す

- 状態: 受理
- 日付: 2026-11-05
- Issue: #89（GitHub）
- 影響する規則: FR-005 / FR-006 / FR-007 / ARC-011 / EDIT-03・15 / UNDO-01 / KEEP-02・03・05 / BIG-12・13 / ADR 0024 / ADR 0026

## 文脈

2026-11-05 に施主が「行や列を追加できないと、新規で作れないのでは」と気づいた。行と列の挿入と削除（EDIT-03）はフェーズ 1・M2 の項目で、ADR 0024 が差分の形を決めている。

- 層 1「行の並び」（`RowOrder`・原本の行の区間と足した行の列）。core の型は GitHub Issue #87 で置いた
- 層 2「セルの書き換え」（`CellEdits`・行と列は同一性 `RowId` / `ColumnId` で指す）
- 足した行と、列の構造が変わった行は、方言どおりに書く

決まっていないのは画面の側である。

1. 行を足したり消したりした後の、左端の行の番号（今は「ファイルの何行目か」＝原本のレコードの番号 ＋ 1）
2. どのキーで足し、どこに足すか
3. 最後の行で Enter を押したときに行を足すか
4. 消すときに確認するか

## 決定

**行と列の挿入と削除は Excel と同じ見え方と操作にする。行の番号は上から通し番号、キーは Ctrl++ と Ctrl+-、最後の行で行を自動では足さない、消すときは尋ねずに Undo で戻す。**

### 1. 行の番号は上から通し番号（施主の判断 1）

- 左端の番号は、行の並び（`RowOrder`）の位置 ＋ 1。前書きと見出しの行も数える（今と同じ数え方）
- 何も足し消ししていなければ、今と同じ「ファイルの何行目か」になる。保存すれば、通し番号とファイルの行の番号は一致する
- 「行へ飛ぶ」（Ctrl+G）と状態の行の「◯ 行目」も通し番号で数える
- 足した行にも番号が付く。足した印は行の番号の色で示す（書き換えたセルの印と同じ考え）

### 2. 操作とキー（施主の判断 2）

| 操作 | キー | 足す・消す所 |
| --- | --- | --- |
| 行を足す | Ctrl++（JIS の Ctrl+Shift+; と、テンキーの Ctrl++） | カーソルの行の上。行全体を選んでいれば、選んだ行の数だけ上に |
| 列を足す | 同じキーで、列全体を選んでいるとき | 選んだ列の左に、選んだ列の数だけ |
| 行を消す | Ctrl+-（テンキーの Ctrl+- も） | 選んだ範囲にかかる行。列全体を選んでいれば列 |
| 下に行を足す・右に列を足す・末尾に行を足す | パレットだけ | 名前のとおり |

- パレット（Ctrl+Shift+P）には「上に行を足す」「下に行を足す」「末尾に行を足す」「行を消す」「左に列を足す」「右に列を足す」「列を消す」を出す
- 1 回の操作は Undo の 1 手（消した行の書き換えも一緒に戻る）
- 編集中（セルの欄が開いている）に押したら、確定してから行う（ADR 0026 の表の並びを変える操作と同じ）

### 3. 最後の行で Enter を押しても行を足さない（施主の判断 3）

- Excel と同じく、最後の行で止まる。行は明示の操作でだけ増える（開いたファイルを知らずに変えない）
- 新規作成（EDIT-15）で下へ打ち進めるときは「末尾に行を足す」か Ctrl++ を使う

### 4. 消すときに尋ねない（施主の判断 4）

- すぐ消し、状態の行に「3 行を消しました（Ctrl+Z で戻す）」と出す
- 消した行のセルの書き換え（層 2）は捨てずに持つ。並びに無い行の書き換えは、保存でも表示でも使わない。Undo で並びに戻れば、書き換えも戻る

### 5. 推しで決めた細目（書き方）

- **足した行の終わり方**は、ファイルで最も多い終わり方（`FormatSummary` の数）。終わり方が 1 つも無いファイルは CRLF（Windows と Excel）
- **終わり方の無い最後の行の後ろに足す**ときは、その行の後ろに上の終わり方を書いてから足す（行がつながらないように）。最後の行を消して、新しい最後の行が終わり方で終わっても、そのまま書く
- **足した行のセルの数**は表の列の数。書いていないセルは空のセル。引用の方言で、列が 1 つの表の空の行は `""` と書く（ADR 0024 の決定 4 の、空の行にしない規則と同じ）
- **足した列**は、原本の行では行の終わり（終わり方の前）に足すか、間に挟むなら区切りと空のセルを挟む。どちらも、その行は「構造が変わった行」として、触っていないセルのバイト列を写して組み立てる（ADR 0024 の施主の判断 4・5 と同じ組み立て）
- **索引を作り終える前**（BIG-12）は、見えている所への挿入と削除はできる。「末尾に行を足す」と、ファイルの終わりにかかる削除は、索引ができるまで待つ（知らせる）

## 強制

- **planned（実装の Issue で active にする）**:
  - 行の並びの操作と逆の操作が組になること（GitHub Issue #87 の無作為のテスト）
  - 足し消しした表を保存して読み直すと、画面の並びと同じになり、触っていない行はバイト列のまま（保存の往復の無作為のテストを広げる）
  - Undo で全部戻すと、差分が開いた直後の形に戻る
- **不能（レビュー事項）**:
  - 行の番号・状態の行・「行へ飛ぶ」が同じ数え方か

## 結果

得られるもの:

- 空の行と列を足して、新しい表を打てる（新規作成 EDIT-15 の土台）
- Excel から来た人が、同じキーで同じことができる

失うもの・残る穴（**正直に**）:

- 🔴 **足し消しした後は、左端の番号がファイルの行の番号と合わない**（保存するまで）。ローダーのエラーの「1234 行目」と照らすときは、保存してから開き直すか、足し消しの前に照らす
- 列を足すと、その表の全部の行が「構造が変わった行」になり、保存で全部の行を組み立て直す（バイト列は写すので値は変わらないが、時間は行の数に比例する）
- 行の番号の色だけで「足した行」を示すのは、色の見分けに頼る（A11Y-01 の課題として残す）

## 施主の判断（2026-11-05・GitHub Issue #89）

下の表の推しを、すべて受理した。

| # | 問い | 推し | ほかの案 |
| --- | --- | --- | --- |
| 1 | 行の番号 | 上から通し番号（Excel と同じ） | ファイルの行の番号のまま（足した行は「+」・消した所は飛ぶ。ローダーのエラーと照らしやすいが Excel と違う） |
| 2 | キーと足す位置 | Excel と同じ（Ctrl++ で上に・Ctrl+- で消す・パレットにも） | パレットだけ（誤操作は減るが手数が増える） |
| 3 | 最後の行で Enter | 足さない | 足す（打ち進めやすいが、意図せず行が増える） |
| 4 | 消すときの確認 | 出さない（Ctrl+Z で戻す・状態の行で知らせる） | 出す |

### キーの衝突の解決（2026-11-06・GitHub Issue #103）

決定 2 の Ctrl++ と Ctrl+- は、ADR 0020 の文字の大きさのキーと同じだった。施主の判断で、Ctrl++ と Ctrl+- は行と列の足し消しにし、文字の大きさは Ctrl+ホイールと Ctrl+0 に寄せた（ADR 0020 の「施主の判断」）。意図は `InsertHere` と `RemoveHere` で、列全体を選んでいて行全体ではないときは列に、そうでなければ行に効く（すべてを選んでいれば行）。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 消した行の書き換えを捨てる | Undo で行を戻したときに、書き換えが失われる |
| 足した行を原本の終わり方の流儀でなく、いつも LF で書く | Windows と Excel の表に LF が混じる（改行の混在 OPEN-08 を自分で作る） |
