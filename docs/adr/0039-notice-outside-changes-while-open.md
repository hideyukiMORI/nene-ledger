# ADR 0039 — 外からの変更は、窓が前面に来たときと保存の前に印を比べて知り、書き換えが無ければ読み直しを勧め、あれば保存を止めて選ばせる

- 状態: 受理
- 日付: 2026-11-16（受理 2026-11-16）
- Issue: #517（GitHub）
- 影響する規則: FR-003 / FR-019 / FR-023 / ARC-001 / ARC-007 / ARC-011 / FILE-01・04 / ADR 0005 / ADR 0025 / ADR 0028

## 文脈

FILE-01（外部の変更の検出：原本が変わったら示し、保存を止めて選ばせる）は、保存の側だけが入っている。

- 開く前に取った印（大きさ・更新日時・Unix の dev と inode・`FileStamp`）を、保存の前と置き換えの直前に比べ、違えば書かない（`SaveFailure::ChangedOutside`・GitHub Issue #60・#71）。知らせは「開いた後にほかのアプリがファイルを変えたので、上書きしませんでした」
- **開いている間には何も示さない**（FR-019 の「開いた後に他のプロセスがファイルを変えたら示す」）。利用者は、直して Ctrl+S を押して初めて知る。そのときには書き換えがたまっている
- 窓が前面に来たことを UI は application に伝えていない（X11 の `FocusIn`・Windows の `WM_ACTIVATE` を受けていない）

本製品の窓が見せている行は、**原本を位置で読んだもの**である（ADR 0017）。原本が外から変わると、索引の目印（バイトの位置）が古くなり、スクロールした先で行の途中から読んだ壊れた表が出うる。知らせるだけでなく、読み直す口が要る。

## 決定

**印を比べるのは、窓が前面に来たときと、保存の前（今までどおり）。違っていたら状態の行で知らせ、書き換えが無ければ「読み直す」を勧め、書き換えがあれば、保存のときに選ばせる（別名で保存・書き換えを捨てて読み直す・やめる）。黙って読み直さない。**

1. **いつ調べるか**：窓が前面に来たとき（UI が合成ルートに知らせ、合成ルートが store の `stamp_of` で印を読んで比べる）。常駐の見張り（ファイルの変更の通知・一定の間隔の読み直し）は置かない。
2. **書き換えが無いとき**：状態の行に「ファイルが外で変わりました · F5 で読み直す」。F5（とパレットの「読み直す」）で、同じ読み方のまま開き直す（索引を作り直す・カーソルの行と列は保つ）。読み直すまでは、スクロールで行を読みに行かない（今の窓の行のまま。動かそうとしたら同じ知らせ）。
3. **書き換えがあるとき**：状態の行に「ファイルが外で変わりました · 直した値は残っています」。Ctrl+S は今までどおり書かずに止め、尋ねる画面（閉じるときの画面と同じ部品）で選ばせる。
   - **別名で保存**（推し・既定）：直した表を別のファイルへ（ADR 0028）。元のファイルは外の変更のまま
   - **書き換えを捨てて読み直す**
   - **やめる**
   - 「上書きする」は出さない。差分は行の番号と原本のバイトの位置に付いているので、変わった原本に重ねると別の行を書き換えうる（`SaveFailure::ChangedOutside` の注記のとおり）
4. **消えた・動かされたとき**（印を読めない）：状態の行に「ファイルが見つかりません」。書き換えがあれば別名で保存を勧める。
5. **自分の保存は外の変更ではない**：保存の後に取り直した印と比べる（今もそうしている）。
6. ネットワークの置き場や同期のフォルダで、中身が同じでも更新日時だけが変わることがある。大きさと更新日時が違えば「変わった」と言い、読み直しても表が同じなら、それでよい（中身のハッシュは取らない。巨大なファイルで窓が前面に来るたびに全部を読めない）。

## 強制

- **active**（テスト・GitHub Issue #551）:
  - 外から変わった間は、表を動かす操作も保存も受けない（application `document` の `a_table_changed_outside_stays_put_until_it_is_reloaded`）
  - 書き換えがあれば、読み直しは 2 度目の求めまで待つ（`reloading_over_edits_needs_a_second_request`・`outside_watch` の `an_edited_table_reloads_only_on_the_second_request`）
  - 外から書き換えたファイルに、差分を重ねて上書きする道が無い（store の `a_file_changed_after_opening_is_not_overwritten` は前からある）
- **planned**: 尋ねる画面（決定 3）と、読み直した後の表が開き直した表と同じことのテスト（今は Xvfb と Windows の exe で見ただけ・gate-proofs 第 106 節）
- **不能（レビュー事項）**: 知らせの文言が、何が起きて何をすればよいかを言えているか（FR-023）

## 結果

- 得るもの：直す前に気づける。書き換えがたまってから「保存できません」と言われない。古い索引で壊れた表を見せない。
- 失うもの：窓が前面に来るたびに、ファイルの情報を 1 回読む（`stat` 1 回・ネットワークの置き場では数十ミリ秒かかりうる）。F5 を 1 つ使う。
- 残る穴：窓が前面のまま外から変わると、次に前面に来るか保存するまで気づかない（常駐の見張りを置かないため）。追記されていくログのような、変わり続けるファイルを見続ける使い方（`tail -f`）は対象にしない。

## 実装して分かったこと（2026-11-16・GitHub Issue #551・#552）

- 決定 2 の「読み直すまでは、スクロールで行を読みに行かない」は、**表を動かす操作と保存の全部を受けない**形で入れた（カーソルを動かすだけでも、窓の外の行を読みに行くことがあるため）。閉じるかを尋ねる画面の答えと Esc は受ける。配色・文字の大きさ・パレットを開くことは受ける。
- 決定 3 の尋ねる画面は、まだ無い。代わりに、書き換えがあるときの F5 は一度「直した値を捨てて読み直すなら、もう一度 F5」と尋ね、続けてもう一度 F5 で読み直す（選べる 3 つのうちの「書き換えを捨てて読み直す」と「やめる」だけ）。
- 🔴 決定 3 の「別名で保存」には穴がある。今の保存は、原本が外から変わっていると別名で保存も止める（GitHub Issue #126）。原本がその場で書き換えられていれば、触っていない行の古い中身はもう読めないので、古い表を別名で書けない。置き換えられたとき（Linux では開いたままの口が古い中身を指す）だけ書ける。どうするかは施主の判断（GitHub Issue #552）。それまで、外から変わった後に書き換えを残す道は無い。
- 保存できなかった（`ChangedOutside`）後にも、同じ比べ方で確かめて、読み直すまで動かさない。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| OS の変更の通知（`ReadDirectoryChangesW`・inotify）で常に見張る | Unix の側は std に無く、依存が要る（ARC-013）。同期のフォルダでは通知が大量に来る。前面に来たときに 1 回比べれば、利用者が戻ってきた時点で分かる |
| 一定の間隔（数秒ごと）で印を読む | 何もしていない窓が、ネットワークの置き場を読み続ける。スリープからの復帰や切れた置き場で失敗を繰り返す |
| 書き換えが無ければ、黙って読み直す（多くのエディターの既定） | 見ていた行が黙って変わる（FR-023）。読み直しは索引を作り直すので、巨大なファイルでは数秒かかり、何が起きたか分からない |
| 書き換えがあっても「上書きする」を選べるようにする | 差分は古い原本の行の番号とバイトの位置に付いている。変わった原本に重ねると、違う行を書き換える |

## 施主の判断（2026-11-16・GitHub Issue #545）

施主は、下の問いのすべてを**推しのとおり**とし、受理した（「推しで受理・マージ」）。実装の後に実機で見て判断が変われば、新しい ADR か追記で直す。

### 尋ねたこと

1. 調べるのは**窓が前面に来たとき**だけでよいか（推し）
2. 書き換えが無いとき、**知らせて F5 で読み直す**でよいか（推し）。黙って読み直すほうがよいか
3. 読み直しのキーは **F5** でよいか（ブラウザーとエクスプローラーと同じ。今は空いている）
4. 書き換えがあるときの選び方は「別名で保存・捨てて読み直す・やめる」の 3 つでよいか（「上書き」は出さない）
