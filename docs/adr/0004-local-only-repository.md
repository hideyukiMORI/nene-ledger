# ADR 0004 — リモートを置かない。Issue はリポジトリの中のファイル、PR の代わりは統合記録と squash

- 状態: 置換（→ [0021](0021-public-repository-on-github.md)・2026-11-04）
- 日付: 2026-10-22
- Issue: #1
- 影響する規則: GIT-001 / GIT-002 / GIT-003 / GIT-004 / QLT-005 / QLT-010 / QLT-012

## 文脈

施主は「git は初期設定するが、リモートリポジトリは無し」と決めた（2026-10-22）。作業の内容を手元の外に出さないためである。
先行の NeNeDocket は GitHub の Issue・PR・CI（`make ci`）・ruleset を前提にしている（GIT-001〜004・QLT-005）。そのまま写すと、規則の置き場が存在しない。

## 決定

**リモートを置かない。GitHub の Issue・PR・CI の役割を、リポジトリの中のファイルとローカルの手順に置き換える。**

1. **Issue は `docs/issues/NNNN-kebab.md` のファイル。** 番号は 1 から連番で、コミットの `(#N)` はこの番号を指す。中身は NeNeDocket の Issue と同じ欄（問題と根拠・意図する結果・規則 ID・受け入れ条件・検証の計画・やらないこと）
2. **PR の代わりは Issue のファイルの末尾の「統合記録」。** 欄は NeNeDocket の PR テンプレートと同じ（目的・正典経路・規則 ID・振る舞いの変更・確認する退行・検証・再利用・抑制・残るリスク）に、統合のコミットを足す
3. **統合は `git merge --squash` で `main` に 1 コミット。** 件名は GIT-003 の形。作業ブランチは統合の後に消す
4. **CI の代わりは統合の前の `make ci`**（Issue #2 で置く）。Git 規約・統合記録の欄・空白を見る。将来 CI を置くなら、それは `make ci` を呼ぶだけにする（QLT-005）
5. Issue のファイルを置くコミットだけは `main` に直接してよい（作業ブランチを切る前に、何をするかを `main` に記録するため）

## 強制

- **planned**: `make ci`（件名の `(#N)` に対応する Issue のファイル・ブランチ名・統合記録の欄）と `.githooks/commit-msg`（GIT-003）。Issue #2 で置いて測る
- **不能に近い**: `main` への直接のコミット・squash 以外の統合・force push を拒む層が無い（GitHub の ruleset に当たるものが無い）。`pre-commit` で `main` 上の直接のコミットを拒む方法（squash の途中は `.git/SQUASH_MSG` がある）を Issue #2 で検討する

## 結果

得られるもの:

- 作業の内容が手元の外に出ない
- Issue と判断の記録がコードと同じ履歴に残り、`git log` と `docs/issues/` だけで追える
- GitHub が無くても、NeNeDocket の規約の形（Issue → 枝 → 記録 → 検査 → squash）をほぼそのまま保てる

失うもの・残る穴（**正直に**）:

- 🔴 **フックの迂回（`--no-verify`）を止める層が無い。** NeNeDocket では CI が PR の全コミットを同じ検証器で見直していた。ここでは `make ci` が `main` の履歴を見直すことでしか見つけられない
- 🔴 **バックアップが無い。** リモートはバックアップも兼ねていた。WSL の仮想ディスクが壊れれば全部失う。バックアップの手段（作業の内容を手元の外に出さずに済む方法）は施主が決める
- レビューは施主と AI の 2 者で、PR の画面のような差分の見え方は無い。`git diff main...<枝>` で見る

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| GitHub の private リポジトリを置く | 施主が「リモートは無し」と決めた。作業の内容を外に出さない方針とも合わない |
| Issue を `docs/todo/current.md` の 1 枚で管理する | 作業単位ごとの問題・受け入れ条件・統合記録が混ざる。番号と件名の `(#N)` の対応も取れない |
| GIT-001〜004 を捨てる | 「一つの変更は一つの Issue から」「件名は判断」は、リモートが無くても価値がある。置き場を変えれば守れる |
| 統合を fast-forward か merge commit にする | NeNeDocket と同じく「1 Issue = `main` の 1 コミット」にしておくと、履歴から Issue を引ける。squash に揃える |
