# ADR 0012 — 配色は nene-nib の組み込み 125 テーマを写し、画面の色は本文の 3 色から整数の補間で導く。希望は設定に残し `system` は OS の明暗に従う

- 状態: 受理
- 日付: 2026-10-22
- Issue: #6
- 影響する規則: ARC-001 / ARC-004 / ARC-007 / ARC-009 / ARC-011 / RS-007 / RS-016 / QLT-008。FR-035 を足す

## 文脈

施主の要望（2026-10-22）: 「カラーリングテーマも同様に導入してね」。NeNeDocket の ADR 0012 は nene-nib の組み込み 125 配色（名前・明暗・背景・前景・強調・作者・許諾・出典）を写し、画面の 8 色を 3 色から整数の線形補間で導き、全配色で字と背景のコントラスト 4.5 以上をテストで要求した。
NeNe Ledger の色の役割は NeNeDocket より多い（表の交互の行・選択・見出し・固定した行と列・見えない文字の印・壊れた行・違反のセル・数式に見えるセル・タイトルバー・窓の縁）。

## 決定

**配色の元は `ThemeSeed`（名前・明暗・背景・前景・強調・作者・許諾・出典）の表で、nene-nib の 125 配色を順も値もそのまま写す（NeNeDocket の `theme_catalog` 経由）。画面の色の役割（`Paint`）はすべて `theme_derivation::derive` が明暗ごとの百分率の表から導く。希望は `ThemeChoice`（`system` か名前）として版付きの設定に残し、`system` は起動時に観測した OS の明暗の既定にする。**

1. **表**: 125 行。名前は小文字とハイフン。出典の URL はアプリが読みに行かない
2. **導出**: sRGB の値のまま整数の線形補間。百分率の表は NeNeDocket から始め、NeNe Ledger の役割（交互の行・見出し・固定・印・違反・タイトルバー・縁）の分を足す。**見た目は仮**で、施主が見て表の数字だけを変える
3. **コントラスト**: 全配色で、字と背景・字と面・字と交互の行・字と選択が 4.5 以上（WCAG 2 の相対輝度）であることを core のテストが要求する。違反のセルや数式に見えるセルなど**色だけで意味を伝えない**（印の形も変える・A11Y-02）
4. **高コントラスト**: OS のハイコントラストの設定（Windows）が有効なら、OS の色を使う配色を選べる（A11Y-02）
5. **希望と表示の分離**: 設定は `theme = system|<name>`。`system` は OS の明暗（Windows は `AppsUseLightTheme`、X11 は GTK の慣習（`GTK_THEME` / `settings.ini`）・NeNeDocket Issue #48）。起動後の OS の変更には追従しない
6. **フレームが配色を運ぶ**: 表示フレームが解決した配色を持ち、UI は役割から色を引く。UI に色のリテラルは無い（ARC-011）。タイトルバーと窓の縁も同じ配色から描く（ADR 0013）
7. **利用者のテーマファイル**（nene-nib の `.v1.theme`）はフェーズ 3（THEME-05）

## 強制

- **active（実装後）**: 全配色のコントラストと名前の一意性のテスト（core）。導出は整数だけで決定的（Issue #34 で実装: `theme_derivation` と `theme_catalog` のテスト）
- **planned**: UI に色のリテラルを書かない字句検査（CNF の追加は実装の Issue で検討）

## 結果

- 得るもの: 125 配色が Windows と X11 で同じ表から出る。nene-nib・NeNeDocket と同じ見えをそろえられる
- 失うもの: 導出の百分率は施主の目を通していない
- 残る穴: X11 の明暗の観測は GTK の慣習だけ。KDE などは別の Issue

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 役割の色を 125 配色ぶん手で書く | 数千の値を目で決められない。3 色から導き、要る配色だけ後で上書きする |
| ライトとダークの 2 つだけ | 施主が「同様に」を求めた。表を写すだけなので費用は小さい |
| OS の明暗の変化に追従する | 起動時の観測で足りる。追従は UI が時間と OS を読む経路になる（ARC-007） |
