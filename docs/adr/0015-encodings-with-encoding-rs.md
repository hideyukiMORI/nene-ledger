# ADR 0015 — 文字コードは `encoding_rs` で復号・符号化する。ただし原本のバイト列は復号した結果から作り直さない

- 状態: 受理
- 日付: 2026-10-22
- Issue: #8
- 影響する規則: ARC-001 / ARC-008 / ARC-013 / CNF-013。FR-002・OPEN-09・OPEN-10・JP-01〜03・KEEP-02・KEEP-03・SAVE-03・SAVE-04

## 文脈

UTF-8（BOM の有無）・UTF-16LE / BE・Shift_JIS（CP932）・EUC-JP・Latin-1 / CP1252 を読み、表示し、書き出す（FR-002）。文字コードの表は大きく、自前で書くほうが危険（DEVELOPMENT_WORKFLOW 第 6 節）。
NeNeDocket は `encoding_rs` 0.8 を store に入れ、`Shift_JIS` の CSV の添付を読んだ（NeNeDocket ADR 0017）。

## 決定

**文字コードの表は `encoding_rs` に任せる。scan が表示のための復号を、store が書き出しのための符号化を行う。ただし保存では、触っていないセルを復号して符号化し直すことはせず、原本のバイト列をそのまま写す（ADR 0005）。**

1. **導入**: scan と store を作る Issue で、`encoding_rs`（`default-features = false`・必要な機能だけ）を足し、`deny.toml` の `allow` を実測で更新し、CNF-013 の許可表と CODING_RULES 第 5 節の表に 1 行ずつ足す
2. **判別**（OPEN-09）: BOM → 先頭の量（決め打ちしない・64 KiB）が UTF-8 として正しいか → CP932 / EUC-JP として正しいか → 確信が無ければ候補を示して選ばせる（FR-023）。判別の規則は core の純関数（バイト列を見るだけ・依存なし）、表を引く復号は scan
3. **往復**（KEEP-02・KEEP-03）: 表示は復号した文字列、保存は原本のバイト列。編集したセルだけを符号化する。だから復号と符号化で往復しない文字（波ダッシュなど）も、**触っていない所では変わらない**
4. **保存の前の検査**（SAVE-04・JP-02・JP-03）: 編集したセルと書き出し先の文字コードで、表せない文字・往復で変わる文字を一覧する。置換の候補は示すが、勝手に置き換えない
5. **CP932 と JIS の Shift_JIS**（JP-01）: `encoding_rs` の `Shift_JIS` は WHATWG の定義で、Windows の CP932 に寄せた表である。JIS の Shift_JIS（拡張を持たない）を区別するのは「その表で表せるか」の検査として自前で持つ（表は JIS X 0208 の範囲の判定だけ）。0x8160 などが Unicode のどの文字に復号されるかは、実装の Issue でテストで確かめて記録する【要確認】

## 強制

- **active（既存）**: CNF-013 は、表に書くまで scan と store の外部クレートを拒む
- **planned**: 往復のバイト一致のテスト（QLT-008 の 3）を、Shift_JIS・UTF-16・BOM 付きのファイルで（M2）

## 結果

- 得るもの: 文字コードの表を自前で持たない。触っていない所は文字コードに依らず変わらない
- 失うもの: 依存が 1 つ増える（scan と store）
- 残る穴: UTF-16 は「1 行の区切り」と「区切り文字」がバイトの単位で探せないので、速い経路（SIMD）は UTF-8 / ASCII 互換の文字コードでだけ効く。UTF-16 は復号してから切るか、2 バイト単位で探すかを、scan の Issue で測って決める

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 文字コードの表を自前で書く | 表が大きく、誤りの危険が大きい |
| 開くときに全体を UTF-8 に変換して持つ | 巨大なファイルでは時間と記憶を食い、保存で元の文字コードのバイト列を失う（ADR 0005） |
| OS の変換（`MultiByteToWideChar` / iconv） | OS ごとに表が違い、Windows と X11 で結果が変わる（FR-022） |
