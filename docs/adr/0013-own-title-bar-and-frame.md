# ADR 0013 — 窓のタイトルバーと枠も自前で描く。ただし移動・リサイズ・スナップ・影は OS の仕組みに乗る

- 状態: 受理
- 日付: 2026-10-22
- Issue: #6
- 影響する規則: ARC-005 / ARC-011 / RS-010 / QLT-013。FR-025 を改める。ADR 0002 の決定 1〜4 に足す

## 文脈

施主の要望（2026-10-22）: 「ウィンドウのヘッダーや枠も使わないで独自に描画で」。SPECIFICATION の FR-025（窓は OS の通常の窓）と食い違うので、FR-025 を改める。
nene-ruler は飾りのない窓を X11 と Windows で自前で描いた実績がある（nene-ruler ADR 0005 / 0008）。NeNeDocket は通常の窓に戻した（NeNeDocket ADR 0002・FR-018）。

タイトルバーと枠を自前にすると、OS が無料でくれていたものを失いやすい: 端へのドラッグでのスナップ・Windows 11 の Snap Layouts（最大化ボタンの上で出る配置の選択）・影と角丸・`Alt+Space` のシステムメニュー・ダブルクリックで最大化・枠のリサイズのカーソル・スクリーンリーダーがボタンを読むこと。

## 決定

**タイトルバー（アプリ名・ファイル名・未保存の印・最小化・最大化・閉じる）と窓の縁は、表と同じ部品の核（core の配置と当たり判定）で自前で描く。ただし移動・リサイズ・スナップ・影・システムメニューは OS の仕組みに乗り、自分で真似しない。**

1. **Windows**: 通常の窓の型（`WS_OVERLAPPEDWINDOW`）のまま、`WM_NCCALCSIZE` でクライアント領域を窓全体に広げてタイトルバーと枠を消す。`WM_NCHITTEST` で core の当たり判定を OS の領域に写す（`HTCAPTION`・`HTLEFT` などの縁・`HTMINBUTTON`・**`HTMAXBUTTON`（Windows 11 の Snap Layouts が出る）**・`HTCLOSE`）。影は DWM（`DwmExtendFrameIntoClientArea`）、角丸は `DWMWA_WINDOW_CORNER_PREFERENCE`。こうすると、スナップ・`Win+矢印`・ダブルクリックで最大化・`Alt+Space` のシステムメニューは OS がそのまま行う
2. **X11**: `_MOTIF_WM_HINTS` で装飾を外し、移動とリサイズはウィンドウマネージャーに `_NET_WM_MOVERESIZE` で頼む（自分で窓を動かさない）。最大化は `_NET_WM_STATE`。ウィンドウマネージャーが応じないとき（WSLg を含む）の振る舞いは実機で測ってから決める
3. **当たり判定は core**: タイトルバーの領域・ボタン・縁の幅は core が物理画素で計算し、UI は OS の領域の番号に写すだけ（ARC-011）。倍率が変わっても崩れない（FR-021）
4. **見えは配色から**: タイトルバーと縁の色は配色の役割から（ADR 0012）。窓が非アクティブなときの色も役割で持つ
5. **キーボードとスクリーンリーダー**: 最小化・最大化・閉じるはキーボードでもできる（システムメニュー・ショートカット）。ボタンを UI Automation に載せるのは A11Y-04 と一緒にフェーズ 2（WIN-11）
6. **全画面**（F11）はフェーズ 2（WIN-10）

## 強制

- **active（実装後）**: 当たり判定の純関数のテスト（core・倍率ごと）
- **planned**: スナップ・Snap Layouts・影・システムメニューは Windows の実機でしか確かめられない（QLT-013）。X11 の移動とリサイズは Xvfb ではウィンドウマネージャーが無いので、実機（WSLg・Xorg）で確かめる
- **不能**: 「OS の振る舞いを自分で真似していないか」はレビュー事項

## 結果

- 得るもの: タイトルバーにファイル名と状態（未保存・読み取り専用・方言）を自由に置ける。配色がタイトルバーまで一貫する
- 失うもの: OS の更新でタイトルバーの作法が変わっても自動では追従しない。`unsafe` の量が Windows の 2 クレートで増える
- 残る穴（**正直に**）:
  - 🔴 **WSLg（Wayland の上の XWayland）で `_NET_WM_MOVERESIZE` が効くかは分からない。** 効かなければ X11 での移動とリサイズの方法を ADR で決め直す
  - 🔴 Windows の `WM_NCCALCSIZE` の扱いは、最大化したときに画面の外へはみ出す・タスクバーに重なるといった細かい罠が多い。実機で確かめるまで「動く」と書かない
  - スクリーンリーダーがタイトルバーのボタンを読めるのはフェーズ 2 から

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| OS の通常の枠のまま（FR-025 の元の形） | 施主の要望に反する |
| `WS_POPUP` で枠の無い窓を作り、移動・リサイズ・スナップを自前で真似する | スナップ・Snap Layouts・影・システムメニューを失うか、真似しきれない。OS の仕組みに乗るほうが小さく正しい |
| X11 で窓の移動とリサイズを自前で行う（ポインタを追って窓を動かす） | ウィンドウマネージャーと衝突し、タイル型のウィンドウマネージャーやスナップと相性が悪い |
