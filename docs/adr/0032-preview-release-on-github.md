# ADR 0032 — プレビュー版（0.1.0-preview.1）を、Windows の exe の zip だけで GitHub Releases に置く

- 状態: 受理
- 日付: 2026-11-06（受理 2026-11-06）
- Issue: #177（GitHub）
- 影響する規則: QLT-013 / ARC-013 / ADR 0002 / ADR 0009 / ADR 0021 / ROADMAP の M4（配布の手順）/ DEVELOPMENT_WORKFLOW 第 10 節

## 文脈

ROADMAP は最初の版 0.1.0 を M4 の終わり（フェーズ 1 の 124 項目がすべて `確認済み`）に置き、配布の手順（署名・インストーラーの有無）は M4 で先に決める ADR とした。2026-11-06 の時点で `確認済み` は 21 項目で、0.1.0 は遠い。
一方、M2 の中身（編集・保存・元に戻す・貼り付けと切り取り・検索と置換と正規表現）はおおむね動き、施主は人に触ってもらう版を早く出したい。

2026-11-06 に調べた、配るために足りないもの（nene-origin の日報）:

- タグ・リリース・変更履歴が無い。CI は `make ci`（Git の規約）だけで、配る物を作らない
- 版の表示が無い（DEVELOPMENT_WORKFLOW 第 10 節は「画面の表示は `version` から導出」と決めたが、`--version` も画面の表示も無い）
- 外部クレートの著作権表示を配る物に添えていない（`deny.toml` の注記だけ）
- 独自ライセンス（ADR 0009）の第 2 条は、改変版に「このアプリについて」の画面でクレジットを出すことを求めるが、元のアプリにその画面が無い
- 今日入れた機能を Windows の実機で試していない

## 決定

### 1. 0.1.0 の前に、プレビュー版を出す

- 版は `0.1.0-preview.1`（SemVer の先行版）。直したら `preview.2`・`preview.3` と続ける。GitHub の「プレリリース」の印を付ける
- プレビュー版は ROADMAP の M の終わりの条件を満たさない。**「確認済み」と言わず、できること・まだのことを正直に並べる**（ADR 0008）

### 2. 配る物は Windows の exe の zip だけ

- 中身: `nene-ledger.exe`・`LICENSE`・外部クレートの著作権表示の一覧・短い説明書（日本語を主に、英語を添える）・見本の CSV
- Linux 版は配らない（システムの `libcairo2` に依存するので、配り方を別に決める）

### 3. exe は GitHub Actions でタグから作る

- タグ `v0.1.0-preview.1` を押すと、公開のソースから exe と zip を作り、Releases にプレリリースとして置く。手元で作った exe は配らない（ROADMAP M4 の「配る物を 1 回だけ作ってそのまま出す」）
- 同じ手順を手元でも回せるように、zip を作る入口を Makefile に置く（施主が実機で試す候補の exe もこれで作る）

### 4. タグは、候補の exe を施主が Windows の実機で試してから打つ

- QLT-013（Windows で動かすまで「動く」と書かない）。試した記録は gate-proofs に残す

### 5. コード署名は今は買わない

- 署名の無い exe は SmartScreen が止める（「詳細情報 → 実行」で開ける）。説明書とリリースの説明に開き方を書く
- 先の道は Windows Store（ストアに出せばストアの側で署名される・施主 2026-11-06）。そのための包み方（MSIX）は別に決める

### 6. ライセンスを整える

- `LICENSE`（ADR 0009）を zip に入れる。条文は今のまま出し、0.1.0 の前に法律の専門家の確認を考える
- 外部クレートの著作権表示の一覧を、`Cargo.lock` から Windows の exe に入るクレートだけを選んで作る（ライセンスの本文と著作権表示）。一覧と `Cargo.lock` が食い違えば検査で落とす
- 「このアプリについて」の画面（パレットから）に、版・著作権・ライセンスの要旨・著作権表示の一覧のありかを出す。`--version` で版を出す

## 強制

- **planned（実装の Issue で active にする）**:
  - 著作権表示の一覧が `Cargo.lock` の Windows の exe に入るクレートと一致する（xtask の検査）
  - `--version` と「このアプリについて」の版が `Cargo.toml` の `version` と同じ（テスト）
  - タグから zip を作る手順が、手元の Makefile の入口と同じ（同じ script を呼ぶ）
- **不能**: ライセンスの条文の解釈。実機で動くこと（施主の確認を gate-proofs に記録）

## 結果

得られるもの:

- 人に触ってもらう版を、0.1.0 を待たずに出せる。誰でも、どのソースから作った exe かを追える
- ライセンスの義務（自分の LICENSE・外部クレートの表示・クレジットの画面）を配る物で満たす

失うもの・残る穴（**正直に**）:

- 署名が無いので、最初の起動で SmartScreen の警告が出る
- プレビュー版は 124 項目の多くが未着手のまま出る。説明に書かないと「壊れている」と受け取られうる
- 独自の条文は専門家の確認を経ていない（ADR 0009 のまま）
- Linux の利用者には配らない

## 施主の判断（2026-11-06・GitHub Issue #177）

施主「プレビュー版だそう。GitHubReleasesで公開。ライセンスも整えて。windowsのexeのzipだけでいいよ」。続けて並べた 6 つの問いに「３は、windowsStoreで出せば署名いらないから今のところは買わないで進めるでいいよ。他は推しでおっけ」。

| # | 問い | 決まったこと | ほかの案 |
| --- | --- | --- | --- |
| 1 | 版の名前 | `0.1.0-preview.1` | `0.0.1` |
| 2 | タグの時機 | 施主が実機で試してから | すぐ打つ |
| 3 | 署名 | 今は買わない（先は Windows Store） | 今から証明書を買う |
| 4 | exe を作る場所 | GitHub Actions でタグから | 開発機で作って手で上げる |
| 5 | 説明の言葉 | 日本語を主に、短い英語を添える | 日本語だけ |
| 6 | ライセンスの専門家の確認 | 今の条文で出し、0.1.0 の前に考える | 確認してから出す |
