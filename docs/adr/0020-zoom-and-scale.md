# ADR 0020 — 文字の大きさの変更は表と詳細ペインの字だけを変え、段階は application が決めて UI が測り直す。固定の画素は画面の倍率の 1 つの経路で掛ける

- 状態: 受理
- 日付: 2026-10-26
- Issue: #37
- 影響する規則: ARC-011 / RS-001 / RS-002 / FR-021。VIEW-12・WIN-09・ADR 0002 / 0013

## 文脈

施主（2026-10-26）:「将来的に、Ctrl+ホイールや、Ctrl++|- でフォントサイズの変更を実装してもらう」。今の字の寸法は UI が字体（Noto Sans CJK JP・14 画素）から 1 度だけ測り（`frame_surface::measure`）、窓の見え（`WindowView`）として application に渡している。行の高さ・タイトルバー・ペインの行は字の寸法から導き、列の幅は字数（`ColumnWidths`）で持つ。一方で、窓の縁 6・角 16・カーソルの枠 2・ペインの帯 3 と余白 6 などは固定の画素である（current.md の一覧）。

字の大きさを変える操作には 2 種類ある。利用者の拡大（Excel・ブラウザーの Ctrl+ホイール。表の中身だけが大きくなり、窓の部品は変わらない）と、画面の倍率（OS の 125% など。窓全体が大きくなる・WIN-09）。

## 決定

**利用者の拡大（`ZoomLevel`）は、表（見出しの行・行番号を含む）と詳細ペインの字だけを変える。タイトルバーと状態の行は変えない。拡大の段階・上限・下限は application の純関数が決め、UI は言われた大きさで字を測り直して、2 組の字の寸法（窓の部品・中身）を渡す。固定の画素は拡大では変えず、画面の倍率を入れるときに 1 つの経路（倍率を掛ける関数）で掛ける。**

1. **段階**: 50・67・80・90・100・110・125・150・175・200・250・300%（Excel とブラウザーに近い）。Ctrl+ホイールの上で 1 段大きく、Ctrl+ホイールの下で 1 段小さく、Ctrl+0 で 100%（パレットの「文字を大きくする／小さくする」も）。🔴 Ctrl++ と Ctrl+- は、2026-11-06 の施主の判断で行と列の足し消しに譲った（下の「施主の判断」）。端では止まる。変えたら状態の行で「文字の大きさ 125%」と知らせる
2. **持ち方**: 今の拡大は配色と同じく合成ルートが持つ（ファイルの画面の状態ではない）。`Session` が今の拡大を返し、UI はそれが変わったら中身の字を測り直す（ARC-011: 段階は決めない）
3. **2 組の字の寸法**: `WindowView` は窓の部品の字の寸法と中身の字の寸法を持つ。表の配置・本体の行の数・詳細ペインは中身の寸法、タイトルバー・状態の行は窓の部品の寸法を使う。文字の描画命令は、どちらの字で書くか（`TextRole`）を持つ
4. **列の幅**: 字数で持つので、拡大しても字数は変わらず、画素の幅だけが変わる
5. **固定の画素**: 拡大では変えない（枠の線が太くならない）。画面の倍率（WIN-09）を入れる Issue で、固定の画素を 1 つの関数に通して倍率を掛ける。それまで、新しい固定の画素を足すときは current.md の一覧に入れる
6. **残す**: 拡大は版付きの設定に残す（設定の Issue まで、起動のたびに 100%）

## 強制

- **active（実装後）**: 段階の純関数のテスト（端で止まる・100% に戻る）。描画命令の字の種類のテスト（表とペインは中身、タイトルバーと状態の行は窓の部品）。1 画面の行の数が中身の寸法から決まるテスト
- **active（Issue #58）**: 画面の倍率と固定の画素の経路（`DisplayScale`・`GlyphMetrics::px`。倍率の計算と 150% の配置のテスト）
- **planned**: 設定への保存
- **不能**: 測り直した字の寸法が見た目どおりか（字体による）は画面で確かめる

## 結果

- 得るもの: 表を大きくしても窓の部品は崩れない。列の幅は字数のまま比例して広がる
- 失うもの: 字の寸法が 2 組になり、`WindowView` と描画命令が少し大きくなる
- 残る穴: 拡大の度に UI が字体を測り直す（軽いが、ホイールを速く回すと続けて測る）。字体の大きさは画素の整数に丸める

## 施主の判断（2026-11-06・GitHub Issue #103）

ADR 0027 で決めた行と列の足し消しのキー（Excel と同じ Ctrl++ と Ctrl+-）が、この ADR の文字の大きさのキーと同じだった。2 つの案を並べ、施主は推しの案 A を受理した（「それでいいよ」）。

| 案 | 中身 | 理由 |
| --- | --- | --- |
| **A（受理）** | Ctrl++ と Ctrl+- は行と列の足し消し。文字の大きさは Ctrl+ホイールと Ctrl+0（とパレット） | 利用者の大半は Excel の人で、Excel も同じ。足し消しは編集の中で何度も使い、文字の大きさは一度決めたらあまり変えない。Excel の拡大も Ctrl+ホイール |
| B | 文字の大きさを今のまま残し、行と列は Ctrl+Shift++ と Ctrl+Shift+- | Excel と違うキーを覚えることになる |

失うもの：ブラウザーや VS Code に慣れた人が Ctrl+- で文字を小さくしようとして行を消すことがある。消すとすぐ状態の行に「◯ 行を消しました（Ctrl+Z で戻す）」と出て、Ctrl+Z で戻せる。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 窓全体（タイトルバー・状態の行も）を拡大する | 窓の部品が大きくなり、狭い画面で表が見えなくなる。Excel もブラウザーも中身だけを拡大する |
| 拡大の段階を UI が持つ | 段階・端・知らせは判断で、application の仕事（ARC-011） |
| 固定の画素も拡大で掛ける | 拡大で枠の線や縁が太るのは不自然。画面の倍率とは別の話 |
