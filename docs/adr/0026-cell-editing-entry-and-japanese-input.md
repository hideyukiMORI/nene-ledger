# ADR 0026 — セルの編集は Excel と同じ入り方にする。日本語は Windows を IMM32 で先に、X11 は当面の貼り付けから

- 状態: 提案
- 日付: 2026-11-05
- Issue: #62（GitHub）
- 影響する規則: FR-005 / FR-020 / FR-007 / ARC-011 / ARC-013 / EDIT-01・10・11 / SAVE-01・02 / WIN-01 / UNDO-01 / ADR 0002 / ADR 0014 / ADR 0024 / ADR 0025 / NeNeDocket ADR 0020

## 文脈

M2 の最初の縦切り（1 セルの書き換え → 保存 → 往復のバイト一致）のうち、保存のエンジンは main に入った。

- core と application の保存の計画（GitHub Issue #56）
- store の一時ファイルと置き換え（#58）
- 書く前の確かめ（#60）

残りは画面の側で、次の 4 つが決まっていない。

1. どのキーで編集に入り、編集中のキーがどう動くか
2. 日本語をどう入れるか（FR-020「初期から入れる」）
3. 詳細ペインで直せるようにするか（EDIT-01 は「セルの中で・詳細ペインで」）
4. Ctrl+S から store までの経路と、未保存のまま閉じるとき

今の土台は次のとおり。

- **意図**：application の `Intent` は、`Type(char)`（半角の英数字と記号）・`Erase`・`Confirm`・`Cancel` を持つ。使っているのはコマンドパレットと「行へ飛ぶ」の入力欄だけ
- **入力欄**：カーソル（字の間の位置）も、確定前の文字列（preedit）も無い
- **日本語**：
  - Windows は、IME の確定が `WM_CHAR` で届く。ただし確定前の文字列は見えない
  - X11 は keysym を字にするだけなので、日本語をまったく打てない
  - どちらの OS にも貼り付け（Ctrl+V）が無い
- **姉妹の NeNeDocket**（同じ施主・同じ規約）：
  - 同じ問いを ADR 0020 で決めて実装した。core の `TextEdit` と `Preedit` で約 520 行、ui-win32 の `ime` が約 130 行
  - Windows の IMM32 は、施主の実機で確かめた（NeNeDocket gate-proofs 51.7、Microsoft IME で「想定通り」）
  - 施主の WSLg では、fcitx5 の XIM サーバが立つところまで測ってある（51.15、`fcitx5-module-xorg` と `dbus-launch` が要る）
  - X11 の XIM の受け手は、まだ作っていない
- **この機械**：`fcitx5`・`fcitx5-mozc`・`libxim.so` は入っている。ただし動いていない（`xprop -root XIM_SERVERS` → `no such atom`、2026-11-05）

## 決定

**編集への入り方とキーは Excel に揃える。編集の欄の規則（字・カーソル・確定前の文字列）は core の純関数にし、NeNeDocket の `TextEdit` と `Preedit` を出発点にする。日本語は、Windows を IMM32 で縦切りに入れ、X11 は貼り付けを先に入れる。XIM は別の Issue にする。保存は裏の処理で行い、保存が終わったら開き直す。**

### 1. 編集への入り方（施主の判断 1）

| 操作 | 入り方 | 欄の最初の中身 |
| --- | --- | --- |
| 字を打ち始める（IME の確定前の文字列が始まるのも同じ） | **入力の状態** | 空。打った字だけ（元の値を置き換える） |
| F2・ダブルクリック | **編集の状態** | 元の値。カーソルは末尾 |
| Enter（編集していないとき） | 編集に入らない。カーソルを下へ動かす | — |
| Delete（編集していないとき） | 編集に入らない。選んだセルを空にする（`Text("")`、1 手） | — |

- 元の値は、表示用に切り詰める前の値を使う。原本のセルの値か、差分の値かのどちらか
- 1 MiB で切り詰めたレコード（OPEN-17）のセルは、編集に入らない。理由を状態の行に出す。保存の計画も `TooLong` で止まるので、それと揃える

### 2. 編集中のキー（施主の判断 2）

| キー | 入力の状態 | 編集の状態 |
| --- | --- | --- |
| Enter | 確定して下へ | 確定して下へ |
| Shift+Enter / Tab / Shift+Tab | 確定して上・右・左へ | 同じ |
| ← → ↑ ↓ | **確定してその向きへ動く** | 欄の中でカーソルを動かす |
| Home / End | 確定して動く | 欄の先頭・末尾へ |
| F2 | 編集の状態に替える（カーソルの移動になる） | 入力の状態に替える |
| Alt+Enter | セルの中の改行（`\n`。EDIT-10） | 同じ |
| Esc | やめる。元の値のまま、差分を作らない | 同じ |
| 別のセルをクリック | 確定して、そのセルを選ぶ | 同じ |

- 確定で値が元と同じなら、差分を作らない。Undo の手も積まない
- 原本の値に戻したときも同じで、差分を消す。これで、編集して元に戻してから保存すれば、バイト列まで元に戻る
- 改行は、保存のときにその行の終わり方へ揃える（ADR 0024 の施主の判断 2）
- 貼り付けで届く `\r\n` と `\r` は `\n` に揃える。タブは字として残す（セルの値であり、区切りではない）。ほかの制御文字は捨てる

### 3. 置き場（ARC-011）

| 層 | 置くもの |
| --- | --- |
| core | `TextEdit`（字・カーソル・確定前の文字列・打つ・消す・動く・貼る）と `Preedit`。純関数で、テストはファイル無しで書ける。NeNeDocket から写して、この repo の規約で直す |
| application | `CellEditor`（どのセル＝`RowId`・`ColumnId`、元の値、状態＝入力か編集か、`TextEdit`）。`Document` が 1 つだけ持つ。確定で `CellEdits` に入れ、Undo の手を積む（UNDO-01 の Issue で） |
| UI | 欄の矩形にセルの値と確定前の文字列を描く（下線 1 画素）。キーを意図に変える。意図には次を足す：`Edit`（F2）・`Preedit { text, caret }`・`Commit(String)`（IME の確定と貼り付け）・`Paste` |

### 4. 日本語の入力（施主の判断 3）

- **Windows：IMM32**（NeNeDocket ADR 0020 の決定 1 と同じ。`windows` クレートの `Win32_UI_Input_Ime` を使うので、依存は増えない）
  - `WM_IME_SETCONTEXT` で組み立ての窓を消す
  - `WM_IME_COMPOSITION` の `GCS_COMPSTR` と `GCS_CURSORPOS` を `Intent::Preedit` にする
  - `GCS_RESULTSTR` は `Intent::Commit` にする
  - 候補の窓は、`ImmSetCandidateWindow` で編集中のセルの左下に置く
  - 編集していないときに確定前の文字列が始まったら、入力の状態で編集に入る（表の上で「にほんご」と打ち始められる）
  - `unsafe` は ui-win32 の `ime` に閉じる（ADR 0002）
- **Windows の貼り付け**：`CF_UNICODETEXT` を読む。クリップボードを開く経路は、コピー（`clipboard.rs`）の反対側に置く
- **X11 の当面：貼り付け**
  - Ctrl+V で `CLIPBOARD` の `UTF8_STRING` を求める。コピーで持ち主になる経路（`own_clipboard`）の反対側に置く
  - `INCR`（256 KiB を超える分割の転送）は受けない
  - 他のアプリで打った日本語を、編集の欄に貼れる
- **X11 の XIM**：x11rb の上に XIM のクライアントを自前で書く（NeNeDocket ADR 0020 の (a)。1,000 行規模で、依存は増えない）
  - WSLg でサーバが立つことは測ってある。そこで、Windows の縦切りの後に別の Issue として着手する
  - 🔴 Linux の利用者は少数で、Windows を後回しにしない（CLAUDE.md）。そのため順は Windows が先

### 5. 詳細ペインでの編集（施主の判断 4）

- 最初の縦切りには入れない。詳細ペインは今のまま読むだけにして、編集中の値（確定前の文字列も含む）を映す
- 長い値・改行の多い値を広く直す経路として、M2 の中で別の Issue にする
  - 欄の規則は同じ `TextEdit`（複数行）で、`CellEditor` は 1 つ
  - 編集の経路が 2 つにならないようにする（ARC-001）

### 6. Ctrl+S と保存の後

- Ctrl+S は `Intent::Save`。`Document` が `DocumentEffect::Save` を返し、合成ルートが store の `save` を裏の処理で回す（ADR 0014。10 GB で数十秒かかり、UI を止めない）
- 保存の間は、編集・閉じる・もう 1 度の保存を受けない。状態の行に進み具合を出す。中止は ADR 0025 の判断 4 のとおり（SAVE-02 の中止）
- 保存が成功したら、置き換えた後のファイルを開き直す
  - 判別は前の読み方をそのまま使い、判別し直さない
  - 索引は裏で作り直す
  - `CellEdits` を空にし、新しい印（`FileStamp`）を取る
  - 表示の位置とカーソルは保つ
- 失敗したら、`CellEdits` を保ったまま理由を示す
  - 外からの変更：上書きは選ばせない（ADR 0025）
  - ロック：再試行とやめる
  - 表せない字：その字を示す
  - 一時ファイルが残ったとき：その場所を示す
- **「別名で保存」**（Ctrl+Shift+S）は、この縦切りには入れない。ファイルを選ぶ画面（OS のダイアログか自前か）が要るので別の Issue にする。それまで、上の失敗の選択肢の「別名で」は出さない
- 保存の後に Undo の履歴をどうするかは、UNDO-01 の Issue で決める。セルの書き換えだけなら `Source(n)` の番号は保存で変わらないので、履歴を残せる見込みがある

### 7. 未保存のまま閉じるとき（施主の判断 5）

- 差分が空でないときに閉じようとしたら、「保存する／保存しない／やめる」を尋ねる
- 尋ねる画面の部品の配置と当たり判定は core に置く（ARC-011）。UI は描くだけ
- タイトルバーに未保存の印（`●`）を付ける（WIN-01 の残り）
- 落ちた後の復元（UNDO-03）は M2 の後

## 強制

- **planned（実装の Issue で active にする）**:
  - `TextEdit` の打つ・消す・動く・貼る・確定前の文字列の規則を core のテストで固める。NeNeDocket のテストも写す
  - 「確定で値が元と同じなら差分を作らない」と「元の値に戻したら差分を消す」を application のテストで固める
  - 両方の OS のキーのテストで、決定 1・2 の表のキーが同じ意図になることを固める（今の `key_intent` のテストと同じ形）
  - 編集 → Ctrl+S → 開き直し → 往復のバイト一致を、Xvfb の自動の操作（`xdotool`）で 1 本確かめ、gate-proofs に残す
- **不能（施主の実機）**:
  - Windows の IME（確定前の見え・候補の窓の位置・Esc）は、施主の実機で確かめるまで「動く」と書かない（QLT-013）
  - ATOK などの Microsoft IME 以外は試さない

## 結果

得られるもの:

- Excel から来た人が、説明なしで直せる。表の上で打ち始めれば、日本語でもそのまま入る（Windows）
- 欄の規則が core の純関数になるので、パレット・行へ飛ぶ・セルの編集・のちの検索の欄が同じ規則を使える。パレットの欄も、後で `TextEdit` に移す（パレットで日本語の名前を探せるようになる。AUTO-03 の注の「IME はまだ」）
- 保存が裏の処理なので、10 GB でも画面が止まらない

失うもの・残る穴（**正直に**）:

- 🔴 **X11 では、XIM の Issue が済むまで日本語を直接打てない。** 他のアプリで打って貼る
- 🔴 **「別名で保存」が無い間は、ロックや外からの変更で保存できないとき、逃げ道が「やめる」だけになる。** 差分は失わない。閉じるときも尋ねる
- 1 MiB を超えるレコードのセルは直せない（保存の計画と同じ穴）
- 入力の状態での ← → が確定になるのは Excel と同じだが、知らない人は戸惑う。F2 で編集の状態に替えられることを、キーの一覧（A11Y-01）に出す
- 候補の窓は、欄の左下に置く。カーソルの画素の位置ではない（NeNeDocket と同じ）

## 施主の判断（未決）

| # | 問い | 推し | ほかの案 |
| --- | --- | --- | --- |
| 1 | 編集への入り方 | Excel と同じ（打ち始め＝置き換え、F2・ダブルクリック＝続けて直す、Enter は下へ動く） | Enter で編集に入る（LibreOffice の一部の設定・Modern CSV）／打ち始めでも元の値の末尾に足す（Excel と違い、置き換えたい人が毎回消す） |
| 2 | 編集中の矢印 | 入力の状態は確定して動く、編集の状態は欄の中で動く（Excel と同じ） | いつも欄の中で動く（表を素早く埋めにくい） |
| 3 | 日本語の順 | Windows の IMM32 を縦切りに入れ、X11 は貼り付けを先に。XIM は別の Issue | X11 の XIM も同時に（縦切りが倍になる）／貼り付けだけで IME は後（FR-020 の「初期から」に反する） |
| 4 | 詳細ペインでの編集 | 最初の縦切りには入れず、M2 の中で別の Issue | 同時に入れる（欄が 2 つ・フォーカスの規則が増える） |
| 5 | 未保存で閉じるとき | 「保存する／保存しない／やめる」を尋ねる。タイトルバーに `●` | 尋ねずに閉じる（差分を失う）／自動で退避する（UNDO-03・M2 の後） |

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| セルの編集に、OS の編集の部品（Win32 の `EDIT`・X11 のツールキット）を重ねる | 配色・倍率・字体が表とずれる。X11 にはツールキットが無い（ADR 0002）。欄の規則が OS ごとに 2 つになる（ARC-001） |
| TSF（`ITextStoreACP`）で受ける | IMM32 より大きく、IMM32 は TSF の上で今も動く。NeNeDocket の実機の結果を使えない |
| X11 で IM サーバの D-Bus（fcitx5 / ibus）を叩く | `zbus` 一式の依存が要る（ARC-013）。IM ごとに口が違う（NeNeDocket ADR 0020 の (b)） |
| 編集の欄を UI に持たせ、確定の時だけ application に値を渡す | 確定前の値が application に無いので、詳細ペインに映せない。欄の規則が UI ごとに 2 つになる（ARC-011） |
| 保存を UI のスレッドで同期に行う | 1 GB で約 1 秒、10 GB で十数秒、画面が止まる（benchmarks 第 4 節）。中止もできない |
