# ADR 0036 — 方言を変えた書き出しは、必ず別のファイルへ全部の行を組み立て直して書き、表せない字は書く前に止めて示す

- 状態: 受理
- 日付: 2026-11-16（受理 2026-11-16）
- Issue: #517（GitHub）
- 影響する規則: FR-003 / FR-007 / FR-023 / ARC-001 / KEEP-01〜07 / SAVE-03・04 / JP-02・03・05 / ADR 0005 / ADR 0015 / ADR 0025 / ADR 0028

## 文脈

M2 に残る保存まわりの 5 項目は、1 つの入口にまとまる。

- SAVE-03 方言を変えて書き出す（文字コード・BOM・区切り・改行・引用の方針）
- JP-05 全項目を `"` で囲んで保存（Excel でできない・日本の業務の要望）
- SAVE-04 保存の前の文字コードの検査（表せない文字・往復で変わる文字の一覧と置換の候補）
- JP-02 波ダッシュなど、往復で変わる文字の警告／JP-03 機種依存文字・絵文字の検出

今の土台（コードで確かめた）は次のとおり。

- 保存は「原本 ＋ 差分」を、原本と同じ方言・同じ文字コードで書く 1 経路（ADR 0005・0025）。触っていない行は原本のバイト列を写す（KEEP-02〜07 は 2026-11-16 に確認済み）
- 列を足し消しした保存は、全部の行を組み立て直す道を既に通る（1 GB で約 18 秒・記憶は塊の大きさだけ・benchmarks 第 5 節）
- 符号化は store の `encoded`（`encoding_rs`・ADR 0015）。書き換えた値に表せない字があれば、書く前に止めてセルを知らせる（`SaveFailure::Unrepresentable`・GitHub Issue #393）
- 名前を付けて保存は、Windows は OS の画面、X11 はパレットの欄で道筋を受け、まだ無いファイルに書く道（`SaveTarget::Absent`・ADR 0028）がある
- 書く前の空きの確認（Windows・GitHub Issue #515）・裏の保存・進み具合・Esc でやめる（SAVE-02）がある

決まっていないのは、**方言を変えると「触っていない行はバイト列のまま」が成り立たない**ことの扱いである。Shift_JIS のファイルを UTF-8 にすれば、全部の行のバイト列が変わる。これを Ctrl+S の保存と同じ道に混ぜると、「勝手に変えない」（FR-003）の約束が、どの操作で外れるのかが利用者に分からなくなる。

## 決定

**方言を変えるのは「書き出し」という別の操作にし、必ず別のファイルへ書く。今のファイルと窓はそのまま。表せない字は、書き始める前に全部のセルを調べ、あれば書かずに一覧を示す。**

1. **入口**: パレットの「形式を変えて書き出す…」。段の中で、今の形式を初めの値にして 4 つを選ぶ（読み方の選び直しと同じ並べ方）。
   - 文字コード：UTF-8 / UTF-8（BOM 付き）/ Shift_JIS（CP932）/ EUC-JP / UTF-16LE（BOM 付き）
   - 区切り：カンマ / タブ / セミコロン / 縦棒
   - 改行：CRLF / LF（混在していたファイルは、選んだ 1 つにそろう）
   - 引用符の付け方：要るときだけ（既定）/ すべてのセル（JP-05）
2. **書く先は必ず別のファイル**。選び終えたら、名前を付けて保存と同じ道筋の受け方（ADR 0028 の決定 4）で先を受ける。初めの名前は `元の名前-書き出し.csv`（タブ区切りなら `.tsv`）。今のファイルと同じ道筋は断る。
3. **窓は元のファイルのまま**。書き出しは写しを作るだけで、題名・未保存の印・履歴・差分は変えない（名前を付けて保存は窓が先のファイルへ移る。書き出しは移らない）。
4. **書く中身**は、今見えている表（原本 ＋ 差分・行と列の並び）。全部の行を、選んだ方言で組み立て直す（列を足した保存と同じ道）。引用は、要るときだけなら「区切り・引用符・改行を含むセル」を囲み（セルの書き方の正本 `written_cell` と同じ。前後の空白だけでは囲まない。読み戻しても空白は残る）、すべてなら全部のセルを囲む。「セルが無い」所は書かない（短い行は短いまま・KEEP-05）。
5. **書く前の検査**（SAVE-04・JP-03）：選んだ文字コードで表せない字のあるセルを、書き始める前に全部数える（裏の一括処理・Esc でやめる）。1 つでもあれば書かずに、件数と最初の所を示し、F8 と同じ形でそこへ飛べる。利用者は、値を直すか、文字コードを選び直す。**黙って `?` に置き換えない**（FR-023）。
6. **往復で変わる字**（JP-02）：Shift_JIS（CP932）へ書き出すとき、表せるが読み戻すと別の字になりうる字（波ダッシュ U+301C と全角チルダ U+FF5E・全角マイナス U+2212 と U+FF0D など、CP932 と JIS の Shift_JIS で写しが違う組）があれば、書く前に件数を知らせて、続けるかを尋ねる（表は core に閉じた集合で持つ）。
7. **Ctrl+S は変えない**。原本と同じ方言・同じ文字コードで、触っていない行をバイト列のまま書く。

## 強制

- **planned**（受理の後の Issue で）:
  - 書き出したファイルを同じ方言で読み戻すと、セルの値が元の表と同じ（乱数の表 × 方言・QLT-008 の往復）
  - 書き出しの後、元のファイルのバイト列と窓の差分が変わっていない（store と application のテスト）
  - 表せない字があれば 1 バイトも書かない（先のファイルを作らない）
- **不能（レビュー事項）**: 「黙って置き換えていないか」（FR-023）

## 結果

- 得るもの：UTF-8 ⇔ Shift_JIS・BOM の有無・全項目の引用という、日本の業務で毎日要る変換が 1 つの入口で済む。Ctrl+S の「触っていない所は 1 バイトも変えない」は例外なしのまま。
- 失うもの：パレットの段が 1 つ増える。書き出しは全部の行を組み立て直すので、1 GB で 20 秒ほどかかる（列を足した保存と同じ）。
- 残る穴：引用の方針の「文字列だけ」「なし」（SAVE-03 の文にある残り 2 つ）は入れていない（下の尋ねること 2）。JIS の Shift_JIS と CP932 の区別（JP-01）は別。絞った行・選んだ範囲だけの書き出し（SAVE-06）は M3。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| Ctrl+S の保存に「形式を変える」を足す（その場で変換して上書き） | 触っていない行のバイト列が全部変わる保存が、ふだんの保存と同じキーで起きる。FR-003 の約束の境が見えなくなる。元のファイルも失う |
| 書き出したら窓を先のファイルへ移す（名前を付けて保存と同じ） | 変換した先を続けて直すと、元の方言のファイルが古いまま残り、どちらが正か分からなくなる。写しを作る操作と、作業の場所を移す操作は分ける。先を直したければ開けばよい |
| 表せない字を `?` や似た字に置き換えて書く（Excel・多くのエディター） | 黙って値を変える。取り込み先で文字化けの原因が分からなくなる（FR-023）。置き換えるなら、利用者が検索と置換で自分で行う |
| 読み方の選び直し（文字コードを変えて開き直す）で済ませる | あれは「同じバイト列をどう読むか」で、ファイルは変えない。書き出しは「別のバイト列を作る」で、別の操作 |

## 施主の判断（2026-11-16・GitHub Issue #545）

施主は、下の問いのすべてを**推しのとおり**とし、受理した（「推しで受理・マージ」）。実装の後に実機で見て判断が変われば、新しい ADR か追記で直す。

### 尋ねたこと

1. 書き出しの後、窓は**元のファイルのまま**でよいか（推し）。先のファイルへ移すほうがよいか
2. 引用符の付け方は、初めは「要るときだけ」「すべてのセル」の 2 つでよいか（推し）。「文字列だけ（数に見えないセルだけ囲む）」「なし」も初めから要るか
3. 表せない字は、**書かずに止めて一覧**でよいか（推し）。「`?` に置き換えて書き出す」を選べるようにするか
4. 初めの名前は `元の名前-書き出し.csv` でよいか
