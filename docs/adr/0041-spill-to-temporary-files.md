# ADR 0041 — 記憶に入らない並べ替え・一意の値・集計は、決めた上限を超えたら一時ファイルに退避して合わせる

- 状態: 受理
- 日付: 2026-11-16（受理 2026-11-16）
- Issue: #541（GitHub）
- 影響する規則: FR-004 / FR-010 / FR-013 / FR-023 / ARC-007 / ARC-013 / QLT-008 / QLT-014 / BIG-04・06・07・15 / STAT-01・02 / FILT-01 / ADR 0005 / ADR 0006 / ADR 0014 / ADR 0017 / ADR 0025

## 文脈

M3 の先に決める ADR の 2 つ目（ROADMAP「記憶に入らない処理の一時ファイルへの退避」）。本製品の約束は「巨大でも止まらない・記憶はファイルの大きさに比例しない」（FR-004・BIG-04）で、今は次のように守れている（benchmarks 第 17・21 節）。

- 931 MB・1,222 万行のファイルを開いて直して保存しても、記憶の最大は 24 MB（X11）・53 MB（Windows）
- 例外は、書き換えの数に比例する差分（100 万セルで約 650 MB・上限は ADR 0029 の決定 4）

M3 の処理は、作りとして行の数に比例する記憶が要る。

| 処理 | 要るもの | 1,222 万行での目安 |
| --- | --- | --- |
| 並べ替え（SORT-01） | 行ごとのキーと、並べた順（位置の列） | 順だけで 8 バイト × 1,222 万 ＝ 約 98 MB。キーが文字列なら、列の値の全部（数百 MB〜） |
| 一意の値と頻度（FILT-01・STAT-02） | 種類ごとの値と件数 | 種類が少なければ小さい。ID の列なら列の値の全部 |
| 要約の中央値・分位点（STAT-01） | 列の値の全部を並べたもの | 並べ替えと同じ |
| 絞り込み（FILT-02） | 見せる行の集合 | 1 行 1 ビットで約 1.5 MB（退避は要らない） |

写像（mmap）は製品の経路に入れていない（ADR 0017 の決定 6）。原本と一時ファイルは、位置を指定した読み書きだけで扱う。一時ファイルを書く口は store にある（保存の一時ファイル・ADR 0025）。scan は書き込みの API を使わない（CNF-015）。

## 決定

**行の数に比例する中間の結果は、処理ごとの記憶の上限まで記憶に持ち、超えたら並べた「連」として一時ファイルに書き出し、最後に連を順に合わせる（外部の併合）。上限・置き場・消し方を 1 か所で決める。**

1. **記憶の上限**：一括処理 1 つにつき、既定は 256 MB（設定で変えられる・版付き）。処理は、塊ごとに取り出したキーをこの上限まで溜め、超えそうになったら並べて連を 1 つ書き出す。上限に収まれば、一時ファイルは作らない。
2. **並べ替え**：キーは「比較の方法で読んだ値 ＋ 行の位置」の組（ADR 0040）。連は、キーの順に並べた組の列。最後に、連を k 本ずつ順に合わせて、**行の位置だけの列**（8 バイト × 行の数）にする。この列も上限を超えるなら一時ファイルに置き、窓が要る所だけ位置で読む。
3. **一意の値と頻度**：値をキーに並べ、等しい値をまとめて件数を足す（並べ替えと同じ道）。画面に出すのは上位と件数（STAT-02）で、種類の全部は記憶に載せない。見出しの絞り込みの一覧（FILT-01）は、種類が上限（1 万）を超えたら「種類が多すぎるので、条件で絞ってください」と言い、一覧にしない。
4. **中央値・分位点**：並べ替えの連から、位置で読む（全部を記憶に並べ直さない）。
5. **置き場**：OS の一時フォルダの下に、プロセスごとのフォルダ（`nene-ledger-<プロセスの番号>`）。原本と同じフォルダには置かない（保存の一時ファイルと違い、置き換えに使わない。ネットワークの置き場や同期のフォルダを膨らませない）。
6. **空き**：書き出す前に、置き場の空きを確かめる（Windows は `GetDiskFreeSpaceExW`・GitHub Issue #515 と同じ口）。足りなければ処理を始めずに、要る量と空きを知らせる。
7. **消し方**：処理が終わったら要らない連を消し、結果の一時ファイルは、その見せ方をやめたとき・窓を閉じたときに消す。起動のときに、動いていないプロセスの残したフォルダを消す（前の回が落ちた後の掃除）。
8. **中止と失敗**：Esc でやめたら、書いた一時ファイルを消す。書けなかった（空きが尽きた・権限）ら、処理をやめて理由を知らせ、表は元のまま。
9. **決定性**：連の切れ目（どこで書き出すか）は記憶の上限とスレッドの数で変わるが、合わせた結果は変わらない（等しいキーは行の位置で順を決める・QLT-008）。
10. **クレートの置き場**：一時ファイルを書く・読む・消すのは store（書き込みを持てる区画・ARC-007）。キーを取り出すのは scan（原本を読む）。比べる規則は core（ADR 0040）。処理の状態は application（ADR 0014）。新しい依存は足さない（ARC-013）。
11. **測る**：並べ替えと絞り込みの時間と記憶を、DuckDB・qsv・EmEditor と同じファイルで測って記録する（BIG-15・QLT-014）。「速い」と書くのは、その数字を添えたときだけ。

## 強制

- **planned**（受理の後の Issue で）:
  - 記憶の上限を小さく（数 KB）した版と、十分大きくした版で、並べ替え・頻度・分位点の結果が同じ（乱数の表・QLT-008）
  - 処理の終わり・中止・失敗のどれでも、一時ファイルが残らない（store のテスト）
  - scan が書き込みの API を使っていない（CNF-015 は今も active）
- **不能（レビュー事項）**: 一時ファイルに書く中身（列の値）を、要るより長く残していないか

## 結果

- 得るもの：1 億行でも、並べ替えと要約が記憶を使い切らずに終わる。記憶の使い方が「上限まで」と言い切れる。
- 失うもの：大きな並べ替えは、一時ファイルの読み書きの分だけ遅い。一時フォルダに、列の値の写しが一時的にできる（機密の値がディスクに載る）。
- 残る穴：一時フォルダが暗号化されていない機械では、落ちた直後に値の写しが残りうる（次の起動で消す）。上限の既定（256 MB）は測って決めた数ではない。実装のときに、1 GB のファイルで 64 MB・256 MB・1 GB を測って決め直す。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 全部を記憶に載せて並べる（多くのエディター） | 1,222 万行の文字列の列で数百 MB〜数 GB。約束（FR-004）が、並べ替えたとたんに外れる |
| DuckDB などを組み込んで任せる | ADR 0007 で、分析は自前で作り、DuckDB は比較相手と決めた |
| 一時ファイルを写像（mmap）で読む | ADR 0017 の決定 6（SIGBUS とロックへの備えを決めるまで入れない）。位置を指定した読み出しで足りる |
| 一時ファイルを原本と同じフォルダに置く | 同期のフォルダ（OneDrive・Dropbox）やネットワークの置き場に、大きな一時ファイルが流れる。保存の一時ファイルと違い、同じボリュームである必要が無い |
| 上限を物理の記憶の割合（例: 1/4）で決める | 機械ごとに振る舞いが変わり、再現できない。ほかのアプリの使う量は分からない。決めた数を既定にして、設定で変えられるようにする |

## 施主の判断（2026-11-16・GitHub Issue #545）

施主は、下の問いのすべてを**推しのとおり**とし、受理した（「推しで受理・マージ」）。実装の後に実機で見て判断が変われば、新しい ADR か追記で直す。

### 尋ねたこと

1. 記憶の上限の既定は **256 MB**（設定で変えられる）でよいか。実装のときに測って決め直す前提
2. 一時ファイルの置き場は **OS の一時フォルダ**でよいか（推し）。機密の値が一時的にディスクに載ることを、説明書に書く
3. 見出しの絞り込みの一覧は、種類が **1 万**を超えたら一覧にしない、でよいか
