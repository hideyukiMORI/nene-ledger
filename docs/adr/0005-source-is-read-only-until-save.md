# ADR 0005 — 原本は保存の置き換えまで書かない。編集・変換・並べ替えは原本に重ねる派生値で、触っていない行はバイト列のまま書き戻す

- 状態: 受理
- 日付: 2026-10-22
- Issue: #1
- 影響する規則: ARC-001 / ARC-004 / ARC-005 / ARC-009 / QLT-008 / CNF-015 / FR-003 / FR-004 / FR-005 / FR-007 / FR-011

## 文脈

Excel で CSV を開くと、先頭の `0` が落ち、`1-2` が日付になり、長い数字が指数表記になり、保存で文字コードや引用符が変わる。施主が CSV のエディターを作る動機はここにある。
同時に、10 GB・1 億行のファイルを「開いた瞬間に見える」ようにしたい（FR-004）。全体を記憶に読み込んでセルの文字列の表にする作りでは、どちらも満たせない。

施主との検討（2026-10-22）で、次の土台が先に要ると確かめた。

- 変換は全セルを書き換えず、列にかける規則として持ち、表示で計算し、保存で反映する
- 元のファイルは保存するまで触らない。保存は一時ファイルに書いてから置き換える
- データの中身は文字列のまま持ち、型を推測しない

## 決定

**原本（開いたファイルのバイト列）は、保存の置き換えの瞬間まで書かない。画面に見えている表は、原本 ＋ 差分 ＋ 変換の規則 ＋ 表の見えから作る派生値である。保存では、触っていない行を原本のバイト列のまま書き戻す。**

1. **原本は読むだけ。** 読み取りの区画（scan）は書き込みの API を使わない（CNF-015）
2. **編集は差分。** セルの書き換え・行と列の追加・削除・移動は、原本の位置（行の番号・列の番号）に対する差分として application が持つ。Undo / Redo は差分の列を戻し進めする
3. **変換は規則。** 列への変換（大文字・空白・置換・日付の形式）は `Transform` として持ち、表示するセルに対してその場で計算する。全セルを書き換えない
4. **並べ替え・絞り込みは表の見え。** 行の並びの表（行の番号の列）を作るだけで、原本も差分も変えない。保存のときに「見えている順で保存するか、元の順で保存するか」を利用者が選ぶ
5. **セルは文字列。** 型を推測しない。数や日付として扱うのは、利用者が選んだ比較の方法と変換の規則の側だけ
6. **保存は置き換え。** 原本 ＋ 差分 ＋ 変換の規則から新しい内容を一時ファイル（同じフォルダ）に順に書き、同期してから元の名前に置き換える。Windows は `ReplaceFileW` と再試行、Linux は `rename`。その場の上書きの経路を作らない（ARC-001）
7. **バイト列の約束。** 保存で、差分も変換も当たっていない行は、原本のその行のバイト列（引用符・改行・文字コードを含む）をそのまま写す。編集した行も、**触っていないセルは元のバイト列を写すことを目標**とし、少なくとも行の単位では約束する（FR-003）。BOM の有無・最後の行の改行の有無も保つ
8. **書き出しは別。** 方言（文字コード・区切り・改行）を変えた書き出しは、利用者が明示した変換であり、7 の約束の外にある

## 強制

- **planned**: CNF-015（scan が書き込みの API を使わない）。QLT-008 の 3（触っていない行のバイト一致）のテスト。最初に保存を実装する Issue で、テストと実ファイルの発火を記録する
- **不能**: 「画面の表を正本にしていないか」はレビュー事項（ARC-011）

## 結果

得られるもの:

- 開くのに全体を読む必要が無い。最初の画面は先頭を切るだけで出せる（FR-004）
- メモリはファイルの大きさでなく、行の索引と差分に比例する
- 1 億行への変換の適用が一瞬で終わり、取り消しも規則を 1 つ外すだけ
- 保存の途中で落ちても元のファイルは残る（FR-007）
- 「開いて保存しただけで変わる」ことが構造上起きない（FR-003）

失うもの・残る穴（**正直に**）:

- 🔴 **保存は全体の書き直しである。** 1 セルを直しても 10 GB を書く。置き換えには同じフォルダに同じだけの空きが要る。空きが足りないことを書く前に示す（FR-023）
- 🔴 **原本が外から変えられると、差分の位置が意味を失う。** 外部の変更の検出（FR-019）が要る。検出したら、保存を止めて利用者に選ばせる
- 🔴 **置き換えはファイルの属性を変えうる。** 作成日時・権限・代替データストリーム・ハードリンクは、置き換えで引き継がれないことがある。`ReplaceFileW` が引き継ぐ範囲を Windows の実機で確かめる
- 差分が大きくなると（全行の書き換えなど）、表示の計算が重くなる。差分の持ち方（行ごとの表・区間の木）は実装の Issue で測って決める
- 変換を重ねると、表示のたびに計算する量が増える。重くなったら、変換の結果を一時ファイルに書き出す経路を ADR で足す

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 開くときに全体を読み、セルの文字列の表にする | 10 GB を読み終えるまで何も見えない。メモリがファイルの大きさに比例する |
| 開くときに内部のデータベース（SQLite・DuckDB の形式）に取り込む | 取り込みに時間がかかり、同じデータがもう 1 つできる。型の推測が入りやすい。ADR 0007 |
| 原本をその場で書き換える（変わった所だけ書く） | 行の長さが変わると後ろを全部ずらすことになり、途中で落ちると原本が壊れる |
| 保存で全体を方言どおりに書き直す（引用符を付け直す） | 「触っていない所が変わる」を作る。Excel と同じ過ちになる |
| 型を推測して表示を整える | 製品の存在理由（FR-003）の否定 |
