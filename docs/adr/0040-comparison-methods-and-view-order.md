# ADR 0040 — 並べ替えと絞り込みは原本に重ねる「見せ方」で持ち、比較の方法は列ごとに利用者が選ぶ閉じた集合にする

- 状態: 受理
- 日付: 2026-11-16（受理 2026-11-16）
- Issue: #541（GitHub）
- 影響する規則: FR-003 / FR-009 / FR-010 / FR-023 / ARC-001 / ARC-007 / ARC-011 / QLT-008 / SORT-01〜04 / FILT-01〜03 / KEEP-01・08 / ADR 0005 / ADR 0014 / ADR 0024 / ADR 0027

## 文脈

M3 の先に決める ADR の 1 つ目（ROADMAP「比較の方法（数・日付・自然順）の定義」）。並べ替え（SORT-01〜04）・絞り込み（FILT-01〜03）・列の「見方」（KEEP-08）は、同じ 2 つの問いに掛かっている。

1. **何と何を、どう比べるか。** セルは文字列で、型を推し量らない（FR-003・KEEP-01）。`10` と `9` を数として並べるか文字として並べるかは、利用者が列ごとに選ぶ（FR-009）。
2. **並べ替えた結果は、ファイルの何を変えるか。** 原本は保存まで書かない（ADR 0005）。行の並びを変える層は既にある（`RowOrder`・ADR 0027）。行番号のドラッグ（GitHub Issue #492）はこの層を変え、保存するとその並びで書く。

今の土台（コードで確かめた）は次のとおり。

- 数として読む規則の正本は core の `read_number`（全角の数字・`¥`・`円`・3 桁ずつのカンマ・`▲`・括弧・指数。`%` は数でない・GitHub Issue #41）。選んだ範囲の集計だけが使っている
- 行の並びは `RowOrder`（原本の連続した行と足した行の区間の並び・ADR 0027）。1,200 万行をばらばらに並べ替えると区間が 1,200 万個になり、この形では持てない
- 表示だけの列の入れ替え（`order`・VIEW-02）は、保存に効かない「見せ方」の先例
- 重い処理は裏の一括処理で、原本を目印で分けて並列に畳み、結果は分け方に依らない（ADR 0014・`SplitFold`・QLT-008）
- 画面は窓の分の行しか持たず、行は「行の並びの位置 → 原本のレコード」で読む（ADR 0017・0033）

## 決定

**並べ替えと絞り込みは、行の並び（`RowOrder`）の上に重ねる「見せ方」（どの行を・どの順で見せるか）として持ち、保存は元の順のまま。比較の方法は、列ごとに利用者が選ぶ 5 つの閉じた集合で、規則の正本は core に置く。**

1. **見せ方の層**：`RowOrder` の位置（0 始まり）を見せる順に並べた列（並べ替え）と、見せる行の集合（絞り込み）。どちらも保存には効かない。窓の行番号は、元の位置の番号のまま（並べ替えると番号が飛ぶので、並べ替えていることが分かる）。
2. **保存**（SORT-04）：Ctrl+S は元の順で書く（見せ方を無視する）。並べ替えた順でファイルを書き換えたいときは、パレットの「この並びでファイルを書き換える」（`RowOrder` をその順に置き直す 1 手・Ctrl+Z で戻る）。絞り込んだ行だけを書き出すのは別の操作（SAVE-06・ADR 0036 の書き出しと同じ道）。
3. **比較の方法**（SORT-02）は閉じた集合 `Comparison`：
   - **文字列**：Unicode の符号位置の順（UTF-8 のバイト列の順と同じ）。大文字小文字・全角半角を畳まない。ロケールの照合順は入れない（SORT-06 はフェーズ 2）
   - **数**：`read_number` で読めた値を、10 進のまま比べる（浮動小数に直さない・`1.10` と `1.1` は等しい）
   - **日付**：下の決定 4 の形で読めた値を、年月日（と時刻）で比べる
   - **長さ**：字の数（Unicode の符号位置の数）
   - **自然順**：数字の続き（半角・全角）は数として、それ以外は符号位置の順で、左から比べる（`a2` < `a10`・`第2章` < `第10章`）
4. **日付として読む形**（閉じた集合・初めの版）：`2026-11-16`・`2026/11/16`・`2026.11.16`・`2026年11月16日`・`20261116`（8 桁の数字）と、その後ろに続く時刻（`T` か空白の後の `12:34`・`12:34:56`）。月と日は 1 桁でもよい。年が後ろの形（`11/16/2026`・`16/11/2026`）は、月と日のどちらが先かを推し量れないので、利用者が「月日年」「日月年」を選んだときだけ読む。和暦と曜日・月の名前は初めの版に入れない。
5. **読めない値**（SORT-03）：数・日付として読めない値（空のセル・「セルが無い」を含む）は、昇順でも降順でも**末尾**に集め、その中は元の順。並べ替えた知らせに件数を出す（「数として読めない 12 行は末尾」）。
6. **安定**（SORT-01）：等しい値は元の順を保つ。複数のキーは、1 つ目で等しい行を 2 つ目で比べる。
7. **見方の提案**（KEEP-08）：列の「見方」は、並べ替え・絞り込み・要約で使う比較の方法の既定で、保存にも表示の字にも効かない。並べ替えの段を開いたとき、その列の見えている行のうち数・日付として読める割合を出し（「数として読める 98%」）、利用者が選ぶ。自動では適用しない。初めの値は「文字列」。
8. **絞り込み**（FILT-01・02）：条件は「列・比較の方法・演算（等しい・含む・以上・以下・範囲・空・空でない・正規表現）」の組を AND / OR / NOT でつないだ閉じた木。見出しからの一意の値の一覧（件数付き）は、その列の要約（ADR 0041）から作る。
9. **編集との関係**：並べ替え・絞り込みの間もセルは直せる（書き換えは行と列の同一性に付く）。直した値で順や条件が変わっても、見せ方は**やり直すまで動かさない**（直した行が目の前から消えない）。行を足し消ししたら、足した行は見せ方の末尾に出す。
10. **裏の処理**：キーの取り出しと比較は裏の一括処理（ADR 0014）。分け方とスレッドの数に依らず同じ結果（QLT-008）。大きさの扱いは ADR 0041。

## 強制

- **planned**（受理の後の Issue で）:
  - 比較の規則は core の純関数で、乱数の値で「反射・推移・全順序」を確かめる（QLT-008）
  - 並べ替えの結果が、スレッドの数と塊の切り方に依らない
  - 並べ替え・絞り込みの後に何も直さず保存したファイルが、元のバイト列と同じ（KEEP-02）
- **不能（レビュー事項）**: 「見方」を黙って適用していないか（FR-003）

## 結果

- 得るもの：並べ替えても絞り込んでも、ファイルは 1 バイトも変わらない。数・日付の比べ方が 1 か所の規則になり、集計（今の `read_number`）と同じ読み方で揃う。
- 失うもの：「並べ替えて保存したら、その順で書かれる」という Excel の感覚とは違う（1 手余分に要る）。行番号が飛んで見える。
- 残る穴：日付の形は初めの集合だけ（和暦・英語の月の名前・2 桁の年は読めない値として末尾に行く）。日本語の読みの順（五十音）は入れない。直した後に見せ方をやり直す入口（F5 は ADR 0039 が読み直しに使う案）は、実装の Issue で決める。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 並べ替えを `RowOrder`（保存に効く行の並び）にそのまま書く | 見るために並べ替えただけで、保存するとファイルの行の順が変わる。FR-003 の「勝手に変えない」に反する。巨大なファイルでは区間が行の数だけでき、持てない |
| 列の型を判別して、数に見える列は数として並べる | 型を推し量ることになる（KEEP-01）。郵便番号・商品コードのような「数字の文字列」を数として並べてしまう |
| 読めない値を、昇順では末尾・降順では先頭に置く（Excel） | 向きを変えるたびに、読めない値が画面の頭に出てくる。壊れた値を探すのは絞り込み（「数として読めない」）の仕事にする |
| 数を `f64` に直して比べる | `0.1 + 0.2` の類の丸めで、等しいはずの値の順が実装に依る。集計と同じ 10 進（`Decimal`）で比べる |
| ロケールの照合順（ICU）を入れる | 依存が大きい（ARC-013）。日本語の読みの順は辞書が要る。初めの版は符号位置の順と自然順に限る |

## 施主の判断（2026-11-16・GitHub Issue #545）

施主は、下の問いのすべてを**推しのとおり**とし、受理した（「推しで受理・マージ」）。実装の後に実機で見て判断が変われば、新しい ADR か追記で直す。

### 尋ねたこと

1. 並べ替えは**見せ方だけ**で、Ctrl+S は元の順で書く、でよいか（推し）。並べ替えた順で書くのは「この並びでファイルを書き換える」という別の操作
2. 読めない値は、昇順でも降順でも**末尾**でよいか（推し）
3. 日付として読む形は、上の初めの集合でよいか。和暦（`令和8年11月16日`・`R8.11.16`）は初めから要るか
4. 見方の初めの値は**文字列**で、読める割合を見せて選ばせる、でよいか（推し）。割合が 100% なら数を初めの値にするほうがよいか
5. 直した後、見せ方は**やり直すまで動かさない**、でよいか（推し）
