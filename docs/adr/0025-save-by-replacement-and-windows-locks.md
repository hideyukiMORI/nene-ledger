# ADR 0025 — 保存は store クレートが一時ファイルに書いて置き換える。原本は application のポート越しに読み、Windows の置き換えは adapters-windows に置く

- 状態: 提案
- 日付: 2026-11-05
- Issue: #53（GitHub）
- 影響する規則: FR-003 / FR-007 / FR-019 / FR-023 / ARC-001 / ARC-007 / ARC-013 / CNF-015 / KEEP-02〜04 / SAVE-01・02 / BIG-05 / BIG-14 / FILE-01 / FILE-04 / ADR 0002 / ADR 0005 / ADR 0006 / ADR 0014 / ADR 0024

## 文脈

[ADR 0005](0005-source-is-read-only-until-save.md) の 6 は、保存の方法を決めた。新しい内容を同じフォルダの一時ファイルに順に書き、同期してから元の名前に置き換える。置き換えには、Windows は `ReplaceFileW` と再試行、Linux は `rename` を使う。

[PROJECT_LAYOUT](../PROJECT_LAYOUT.md) は、書き出しを `store` クレートに置くことを承認している。scan と store は互いに依存しない。保存が原本を読むときは、application のポート越しに読む。

最初の縦切りの前に、次の 6 つを決める必要がある。

1. store が原本のバイト列を、どの経路で受け取るか
2. `ReplaceFileW` を、どのクレートで呼ぶか。`unsafe` を書けるのは scan・adapters-windows・ui-win32 の 3 つだけ（[ADR 0006](0006-confined-unsafe-for-scan.md)・[ADR 0002](0002-no-toolkit-x11rb-cairo-win32-direct2d.md)）
3. 10 GB を書いてから失敗しないために、書く前に何を確かめるか
4. 置き換えが失敗したとき、原本と一時ファイルをどう扱うか
5. 属性・権限・リンクをどこまで保つか
6. 保存のあとで、開いているファイルをどう読み直すか

Windows の `ReplaceFileW`（[Microsoft Learn](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-replacefilew)）について、文書から分かることは次のとおり。

- 置き換えた後のファイルは、置き換えられた側の暗号化・圧縮・名前つきストリームを引き継ぐ。ACL も引き継ぐが、`WRITE_DAC` が無いと引き継がない（`REPLACEFILE_IGNORE_MERGE_ERRORS` を付けたとき）
- 3 つのファイルは同じボリュームに無ければならない
- `ERROR_UNABLE_TO_REMOVE_REPLACED`（1175）なら、2 つのファイルは元の名前のまま残る
- `ERROR_UNABLE_TO_MOVE_REPLACEMENT`（1176）・`_2`（1177）なら、置き換えの途中で止まり、名前の状態が変わりうる
- 作成日時を引き継ぐかは、文書からは確かめられなかった。実機で確かめる

scan は、Windows では原本を「読み・書き・削除を妨げない」共有の指定（`FILE_SHARE_READ | WRITE | DELETE`）で開いている。そのため、開いたままでも置き換えられる見込みがある。ただし、Windows の実機ではまだ確かめていない（FILE-04）。

## 決定

**保存の手順は store が持つ。store は、原本のバイト列を application のポート（`SourceBytes`）越しに受け取り、ADR 0024 の行の書き方の判定に従って一時ファイルに書く。書いたら同期して置き換える。置き換えの OS の呼び出しは、application のポート（`Replacing`）として宣言する。Linux の実装は store に、Windows の実装（`ReplaceFileW`）は adapters-windows に置く。**

### 1. 保存の流れ（1 つの経路）

```text
application: 保存の前の確かめ（2）→ 行の書き方の列（ADR 0024 の 4）を作る
   ↓ 裏の処理（ADR 0014・進み具合と中止）
store: 一時ファイルを create_new で作る（原本と同じフォルダ）
     → 行の書き方ごとに書く
         原本を写す区間 … SourceBytes から塊で読み、そのまま書く（続いた区間はまとめる）
         書き換えた行   … 触っていないセルは原本のバイト列、書き換えたセルは方言どおりに符号化
     → flush → sync_all（中身の同期）
     → Replacing::replace(一時ファイル, 原本)
     → Linux はフォルダも同期する
application: 差分を空にし、新しいファイルを開き直す（6）
```

- 書く経路はこの 1 つだけにする。その場で上書きする経路は作らない（ARC-001）
- 書く文字コードは、開いたときの文字コード（BOM の有無を含む）。原本を写す区間は符号化し直さない。書き換えたセルの値は store が `encoding_rs` で符号化する。表せない文字があれば、書く前に止める（SAVE-04・JP-03。一覧は別の Issue で）
- 原本の目印の位置（ADR 0017 の索引）を使い、写す区間の境目を、近い目印から探す。触っていない長い区間は、行ごとに切らずにバイトの区間として写す
- **中止（施主の判断 4）**: 一時ファイルを消す。原本には触れていない

### 2. 書く前の確かめ（10 GB を書いてから失敗しない）

| 確かめ | 方法 | だめなとき |
| --- | --- | --- |
| 外からの変更（FILE-01） | 開いたときの大きさ・更新日時・ファイルの ID（Linux は inode、Windows はファイル ID）と、今のものを比べる | 保存を止め、選ばせる（別名で保存・やめる）。差分の `Source(n)` の意味が変わるので、上書きは選ばせない |
| 空き（SAVE-02） | 書く量の見積もり（原本の大きさ ＋ 差分の増分）と、フォルダのボリュームの空きを比べる | 書き始めない。要る量と空きを示す |
| ロック（FILE-04） | Windows: 原本を削除の権限（`DELETE`）と、すべての共有の指定で開いてみる。Excel が開いていれば共有違反になる | 書き始めない。「ほかのアプリが開いている」と示し、再試行とやめるを選ばせる |
| 書けるフォルダか | 一時ファイルを作れるか（作れなければ、作れなかった理由を示す） | 書き始めない。別名で保存を勧める |

### 3. 置き換えの失敗

- **再試行（施主の判断 3）**: 共有違反（32）・ロックの違反（33）・アクセスの拒否（5）・1175 は、ウイルス対策や検索の索引付けが一時的に掴んでいることが多い。50 ms から倍にしながら、合わせて約 2 秒まで再試行する。それでもだめなら、一時ファイルを残したまま、再試行・別名で保存・やめるを選ばせる
- 1176・1177 で途中で止まったら、元の名前に何があるかを確かめてから知らせる。🔴 **どちらの場合も、一時ファイルを自動では消さない。** 利用者のデータが一時ファイルにしか無い場合があるので、その場所を示す
- Linux の `rename` が失敗したら、原本は元のまま残る。一時ファイルを消して知らせる

### 4. 置き換えの OS の呼び出しはポート `Replacing`

- application に `Replacing` のポート（`trait`）を宣言する。store は、合成ルートから渡されたそれを呼ぶ
- Linux の実装は store に置く。`std::fs::rename` を呼び、その前に `set_permissions` で原本の権限を写す。所有者は写せる時だけ写す
- Windows の実装は adapters-windows に置き、`ReplaceFileW` を `REPLACEFILE_IGNORE_MERGE_ERRORS` で呼ぶ。`unsafe` を書いてよいクレートなので、ADR 0006 の区画は広げない（**施主の判断 1**）
- `windows` の features に `Win32_Storage_FileSystem` を足す。新しい crate は足さない（ARC-013。`deny.toml` は変えない）
- store の外部の依存は、`encoding_rs` だけ（scan と同じ版）。これは PROJECT_LAYOUT の承認の範囲内だが、`deny.toml`・CNF-013 の表・規約 第 5 節の表を、store を作る Issue で更新する

### 5. 属性とリンク

| 対象 | 扱い |
| --- | --- |
| 権限（Linux の mode・Windows の ACL） | 保つ。Windows で `WRITE_DAC` が無く ACL を引き継げなかったら知らせる |
| シンボリックリンク | 行き先のファイルを保存する（リンクを実体のファイルで置き換えない）。保存の前に行き先の道筋を解く |
| ハードリンク（リンクの数が 2 以上） | 置き換えるとリンクが切れる。書く前に知らせ、続けるか・別名で保存するかを選ばせる（**施主の判断 2**） |
| 作成日時・代替データストリーム | Windows は `ReplaceFileW` の引き継ぎに任せる。作成日時は実機で確かめて記録する |
| ファイルの ID・inode | 変わる。保存のあとの「外からの変更」の基準は、新しいファイルで取り直す |

### 6. 保存のあと

- 差分と Undo の束は、保存した時点を「元」として扱う。保存の前の手にも、Undo で戻れるようにする（FR-006）。ただし、戻した状態を保存すると、それは新しい保存になる
- 開いているファイルを、新しい中身で開き直す。最初の縦切りでは、索引を作り直す（裏の処理）。保存で書いた位置から、新しい索引の目印を作る最適化は、測ってから決める（BIG-14）
- 古い原本のハンドルは閉じる。Windows で共有の指定で開いていた古い実体は、閉じたときに消える

### 7. バックアップ（施主の判断 5）

既定では、`.bak` などの前の版を残さない。前の版を残す設定は、M2 の後で足す。残すときは、`ReplaceFileW` の backup の引数を使い、Linux は置き換えの前に hard link で残す。

## 強制

- **planned（最初の縦切りの Issue で active にする）**:
  - CNF-015 を store に広げる形で検査する。原本の道筋を書き込みで開くのは、`Replacing` の実装だけ
  - 往復のバイト一致（KEEP-02・03）を、実ファイルの往復のテストで固める（Pollock の 2,290 ファイル・実データの 392 ファイルを、開いて何もせずに保存し、`cmp` で同じになること）
  - 置き換えの途中で落ちても原本が残ること（SAVE-01）。一時ファイルに書いている途中で止めるテストで固める
  - 保存の往復の時間（BIG-14）を benchmarks に記録する
- **planned（Windows の実機の経路が決まってから）**: Excel が開いているファイルでの確かめ・再試行・ACL と作成日時の引き継ぎを、実機で記録する（QLT-013）
- **不能**: 1176・1177 の状態は、ふつうの試験では起こせない。分岐はレビュー事項にとどめる

## 結果

得られるもの:

- 保存の書き方の大半は、ADR 0024 の core の純関数で決まる。store は、決まった区間を写すことと、符号化と置き換えだけを持つ
- 書く前の確かめで、10 GB を書いてから、ロック・空き・外からの変更で失敗することを避ける
- `unsafe` の区画を広げずに `ReplaceFileW` を呼べる

失うもの・残る穴（**正直に**）:

- 🔴 **1 セルを直しても全体を書く**（ADR 0005 の失うもの）。10 GB では、書く時間とボリュームの空きが要る
- 🔴 **確かめてから置き換えるまでの間に、外から変わりうる**（確かめと使うときがずれる）。置き換えの直前にもう一度だけ確かめ、残りは受け入れる
- ネットワークのドライブ・OneDrive の同期中のフォルダでは、置き換えの意味（同期の衝突・ファイル ID）が保証されない。実機で確かめるまで「保存できる」と書かない
- Windows で原本を開いたまま置き換えられるか（共有の指定の効き目）は、実機でまだ確かめていない
- 合成ルートが `Replacing` の実装を OS で選ぶので、Windows の保存の経路は Linux の `make test` では走らない。`make lint-windows` の型検査と、実機の確認だけになる

## 施主の判断を待つ点

| # | 問い | 推し | ほかの案 |
| --- | --- | --- | --- |
| 1 | `ReplaceFileW` を呼ぶ場所 | adapters-windows（ポート `Replacing`） | store に `unsafe` を許す（ADR 0006 の改訂）／`std::fs::rename`（`MoveFileExW`。ACL・名前つきストリームを引き継がない） |
| 2 | ハードリンクのあるファイル | 書く前に知らせて選ばせる | 黙って切る／その場で上書きする経路を足す（ARC-001・ADR 0005 に反する） |
| 3 | ロックの再試行 | 約 2 秒まで自動で、それから選ばせる | 自動の再試行なし／長く待つ（Excel のロックは解けないので待っても無駄） |
| 4 | 保存の中止 | 一時ファイルを消し、原本はそのまま | 中止を出さない（10 GB で数十秒、待つしかない） |
| 5 | バックアップ | 既定で残さない。設定は M2 の後 | 既定で `.bak` を残す（同じだけの空きがもう 1 つ要る） |

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 原本の変わった所だけを、その場で書き換える | 行の長さが変わると後ろを全部ずらすことになる。途中で落ちると原本が壊れる（ADR 0005） |
| store が scan に依存して、原本を直接読む | PROJECT_LAYOUT が、読みと書きを混ぜることを禁じている |
| 一時ファイルを OS の一時フォルダ（`%TEMP%`・`/tmp`）に作る | ボリュームが違うと、`ReplaceFileW` も `rename` も使えない。写すことになり、途中で落ちると原本が壊れる |
| 書く前の確かめをせず、置き換えで失敗したら知らせる | 10 GB を書いてから、Excel のロックで失敗する |
