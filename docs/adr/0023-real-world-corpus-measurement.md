# ADR 0023 — 実データの突き合わせを、出どころと正解の表をリポジトリに置いて再現できる測定にする

- 状態: 受理
- 日付: 2026-11-05
- Issue: #26・#47（GitHub）
- 影響する規則: QLT-014 / BIG-11 / ARC-013 / ADR 0007

## 文脈

読み方の正しさは Pollock（2,290 ファイル・[benchmarks](../quality/benchmarks.md) 第 1 節）で測ってきた。2026-11-05 の品質の調査（[research](../research/2026-11-05-quality-sweep.md)）では、公開されている実データの CSV（東京都・e-Gov・e-Stat・data.gouv.fr・日本郵便など 392 ファイル）を、正しい文字コードと区切りを与えた Python の `csv.reader` の読みと 1 レコードずつ突き合わせた（benchmarks 第 2 節）。

この突き合わせでしか見えなかった誤りが 3 つある。Pollock には 64 KiB を超えるファイルが 1 つしかなく、日本の表（CP932・e-Stat の表題の行）も無い。

| Issue | 誤り | Pollock で見えたか |
| --- | --- | --- |
| #10 | 64 KiB を超えるファイルで、標本の末尾で切れた字のせいで文字コードを取り違える（日本郵便の UTF-8 版が全部化けた） | 見えない（差 0） |
| #15 | e-Stat の表題の行の見逃し・右の空の列での取りすぎ | 見えない（差 0） |
| #18 | Windows-1252 の文章を CP932 と確信する | 見えない（差 0） |

ところが、突き合わせの道具（Python のスクリプト）とデータはセッションの作業場所に置いたので消えうる。次に判別を変えるとき、同じ突き合わせで退行を確かめられない。

突き合わせには **製品とは別の読み方**（独立した参照）が要る。製品の `--dump` を製品の読み方と比べても、誤りは見えない。いまの参照は Python の `csv` と `codecs` で、このリポジトリの機械（xtask・Makefile）の外にある。

## 決定

**出どころと正解の表は、リポジトリに置く。** `docs/quality/corpus/sources.tsv` に、集まり・ファイル名・URL・大きさ・正しい文字コード・区切り・ある時点の `main` での判定（`exact` / `skipK` / `MISMATCH`）を置く。ファイルそのものは置かない（出どころのライセンスがまちまちで、再配布になる）。

**突き合わせの道具の置き方は、次の 3 つから施主が選ぶ。**

| 案 | 中身 | 得るもの | 失うもの |
| --- | --- | --- | --- |
| A. Python の道具を `tools/corpus/` に置く | 取得（`curl` の一覧）・突き合わせ（`csv` と `codecs`）・判定の表の作り直し。`make bench-corpus CORPUS=<置き場>` が呼ぶ。CI では走らせない | 今日の道具をそのまま残せる。参照が製品と独立 | 依存の許可制（ARC-013）の外に Python を置く。Pollock の採点（`evaluate.py`）と同じ扱いだが、それはリポジトリの外 |
| B. xtask に参照の読み方を書く | xtask に `csv` と `encoding_rs` を足し（ADR ＋ `deny.toml`）、Rust で突き合わせる | 機械が 1 つの言語にそろう | 参照の CSV の読み方を製品と同じ言語・同じ文字コードの表で書くので、独立性が下がる。依存が 1 つ増える |
| C. 道具はリポジトリの外のまま | 表だけを置き、道具は施主の private ワークスペースに置く | リポジトリが変わらない | 次のセッションが道具を探すことになる |

推し: **A**。参照の独立性がいちばん大事で、Python の `csv` は Pollock の採点（第 1 節）と同じ参照になる。CI で走らせないので、`make ci` の決定性（QLT-005）は変わらない。

## 施主の判断（2026-11-05・GitHub Issue #26）

案 **A** を受理した。

- `tools/corpus/fetch.py`（取得）と `tools/corpus/compare.py`（突き合わせ）を置く。Python の標準ライブラリだけを使い、`python3 -I` で走らせる。Python のパッケージは足さない
- `make fetch-corpus CORPUS=<置き場>` / `make bench-corpus CORPUS=<置き場>`。CI では走らせない
- `compare.py` は、表の最後の列（`expected_at_<版>`）と違うファイルを並べ、値の読み違い（`MISMATCH`）があれば終了 1。`--update <版>` で最後の列を書き直す

## 強制

- **active（手で走らせる）**: `make bench-corpus`。判別（文字コード・方言・前書き・見出し）を変える PR では走らせ、変わったファイルを PR の本文に書く。表の判定の列は `--update` で作り直す（2026-11-05 に、起点の `458bf5f` を渡すと `MISMATCH 8` で終了 1 になることを確かめた）
- **planned**: 判別を変える PR で走らせたかを機械で確かめること（今はレビュー事項）
- **不能**: 前書きの行の数が正しいかは、人が見て決めている（`skipK` の K は「その版の判定」で、正解ではない）。正解の列を足すかは別に決める

## 結果

- 得るもの: 判別を変えるとき、日本の表と大きなファイルでの退行を同じ物差しで確かめられる
- 失うもの: URL が切れると取れなくなる（取得日と大きさを残して、変わったことに気づけるようにする）。10 件は 2026-11-05 の控えに URL が無く `-`（取り直すときに埋める）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| ファイルをリポジトリに置く | 出どころのライセンス（CC BY・政府標準利用規約・Licence Ouverte など）がまちまちで、再配布の表示を揃える手間が大きい。日本郵便の 18 MB などで大きさも増える |
| 製品の `--dump` の出力を正解として保存する | 製品が誤っていた所を正解として固めてしまう（#10 の文字化けを正解にしていた） |
