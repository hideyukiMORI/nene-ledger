# ADR 0029 — 複数のセルの貼り付けは左上から束のまま書き、表の端を越えれば行と列を足して 1 手で戻す。切り取りは貼るまで元を消さない

- Issue: #117（GitHub）
- 影響する規則: FR-005 / FR-006 / FR-016 / ARC-001 / ARC-011 / CLIP-01 / EDIT-02・03・16 / UNDO-01 / KEEP-01 / BIG-12・13 / ADR 0024 / ADR 0026 / ADR 0027

## 文脈

施主の要望（2026-11-06「コピーペースト、カットペースト、ドラッグドロップが欲しくなる」・GitHub Issue #105）。

GitHub Issue #115 で、Ctrl+V で OS のクリップボードの文字列を読み、Excel の形のタブ区切りとして行とセルに分けるところ（application の `tsv::parse_tsv`）までを入れた。貼り先は 1 つのセル・編集中の欄・パレットの欄だけで、**表への複数のセルの貼り付けは「まだできません」と知らせている**。

決まっていないのは次のこと。

1. 選んだ範囲と、貼る束（クリップボードの行 × 列）の大きさが違うとき
2. 束が表の端（最後の行・最後の列）を越えるとき
3. 元に戻す（UNDO-01）の単位
4. 大きな貼り付けの上限（記憶と Undo の記憶は貼ったセルの数に比例する・BIG-12）
5. 切り取り（Ctrl+X・EDIT-16）で、元の範囲をいつ消すか。行全体・列全体のとき

今の土台は次のとおり。

- 差分は「行の並び」（`RowOrder`）と「列の並び」（`ColumnOrder`）と「セルの書き換え」（`CellEdits`）の層（ADR 0024・0027）。行と列を足す操作も、セルの書き換えも、それぞれ履歴の 1 手（`EditStep::Rows` / `Columns` / `Cells`）
- 画面は窓の分の行しか持たない。範囲が窓の外にかかるときは、合成ルートが原本から読んで渡す（コピーと集計の 2 段の作り・`DocumentEffect::Copy`）

## 決定

### 1. 貼る所と形

- **選んだ範囲の左上のセルから、束の行 × 列のまま書く**（範囲が 1 つのセルでも広くても同じ）
- 束が **1 つのセル**で、範囲が広ければ、**範囲のすべてのセルに同じ値**を書く（Excel と同じ。列を同じ値で埋める使い方）
- 範囲が束の整数倍でも、繰り返しては書かない（Excel はタイル状に繰り返すが、意図せず大きく書き換える）
- 離れた範囲（Ctrl+クリック）を選んでいれば、最初の範囲の左上から

### 2. 表の端を越えれば、行と列を足す

- 束が最後の行より下・最後の列より右にはみ出したら、**足りない数だけ行を下に、列を右に足して**書く（Excel の格子は無限なので、Excel と同じ見え方になる）
- 行の数が分からない（索引を作っている途中で、束が今読めている所より下に届く）ときは、行の数が分かるまで待つよう知らせる（行の末尾に足す `RowPlace::End` と同じ・ADR 0027）

### 3. 貼り付け 1 回を 1 手で戻す

- 書き換えたセル・足した行・足した列を **1 手（束）** として履歴に積む。Ctrl+Z 1 回で全部戻り、Ctrl+Y で全部やり直す
- 履歴の 1 手に束の形を足す（`EditStep::Batch(Vec<EditStep>)` のような形。中の順に戻し、逆の順にやり直す・実装の Issue で決める）
- 貼った後はカーソルを左上に置き、貼った範囲を選んだ状態にする（Excel と同じ）

### 4. 大きさの上限

- 1 回の貼り付けは **100 万セル**まで、クリップボードの文字列は **64 MiB** まで。超えれば何も書かずに知らせる
- 窓の外の行にかかる貼り付けは、合成ルートが原本の行を読んでから書く（コピーと同じ 2 段・書き換える前の値を履歴に残すため）
- 値は文字列のまま（型を推し量らない・KEEP-01）。Excel の数式は、クリップボードの文字列（見えている値）として来る

### 5. 切り取り（EDIT-16）

- **Ctrl+X は、範囲を点線の枠で示し、クリップボードにコピーと同じ文字列を置く。元はまだ消さない**
- **この窓で Ctrl+V したら、書いた後に元の範囲を空のセルにする**（貼り付けと消すを 1 手）。元の値は先に全部読んでおくので、元と貼る先が重なっても、重なった所は貼った値になる
- Esc・セルの編集・別のコピー・別の切り取りで枠は消え、クリップボードはただのコピーとして残る。ほかのアプリに貼ったときは元を消さない（Excel と同じ）
- 行全体・列全体を切り取って貼っても、**値を動かす**（行と列の並びは変えない）。行と列そのものの移動は、見出しのドラッグ（EDIT-03 の残り）と「切り取った行を挿入」（切り取り中の Ctrl++・Excel の「切り取ったセルの挿入」）を後の Issue で扱う
- 空にするのは空のセル（`""`）。「セルが無い」にはしない（列の数が足りない行は、ADR 0024 の施主の判断 4・5 のとおり間を空のセルで埋める）

## 強制

- **active**（GitHub Issue #146 で入れた）:
  - 束の 1 手を戻すと、書き換え・足した行・足した列がすべて戻る（application のテスト `one_undo_takes_back_a_paste_with_its_added_rows_and_columns`・`pasting_many_cells_writes_from_the_top_left_as_one_step`。履歴の束は `EditStep::Batch`）
  - 1 つのセルの束で広い範囲を選ぶと、範囲のすべてに書く。束が端を越えると、足りない行と列を足す（application のテスト `pasting_one_value_over_a_range_fills_it`・`pasting_past_the_edges_adds_rows_and_columns`）
  - 上限を超える貼り付けは何も書かない（application のテスト `pastes_that_cannot_be_written_change_nothing`。索引を作っている途中で今読める所より下に届く貼り付け・切り詰めた行への貼り付けも同じ）
  - 貼った値を変えない（先頭の 0・日付に見える値・指数表記・application のテスト `pasted_values_are_kept_as_text`・X11 は gate-proofs 第 75 節）
- **active**（GitHub Issue #149 で入れた）:
  - 切り取って同じ窓で貼ると元が空になり（1 手で戻る）、元と貼る先が重なった所は貼った値になる（application のテスト `cutting_and_pasting_in_the_window_moves_the_values_in_one_step`・`a_moved_range_that_overlaps_keeps_the_pasted_values`）
  - Esc・直し始め・表を変える操作で枠が消えた後や、ほかで置いた文字列を貼っても元は残る（application のテスト `a_cut_that_was_dropped_pastes_as_a_copy`。枠を残す意図と消す意図の表は `document::keeps_cut`・閉じた enum の網羅）
  - 離れた範囲は切り取らない（application のテスト `many_ranges_are_not_cut`）
- **planned**:
  - Excel から貼った値が変わらない（Windows の実機・gate-proofs）

## 結果

得られるもの:

- Excel の範囲をそのまま貼って直せる。表の端を越える貼り付けで表を広げられる（新しい表を作るときにも使える・ADR 0028）
- 切り取りは貼るまで何も失わない（間違えて Ctrl+X しても Esc で済む）
- 1 回の貼り付けは 1 回の Ctrl+Z で戻る

失うもの・残る穴（**正直に**）:

- 範囲の整数倍の繰り返し（Excel のタイル）は無い
- 行全体を切り取って貼っても、行は動かない（値だけ動く）。並びを変えるのは後の Issue
- 窓の外にかかる大きな貼り付けは、原本を読む分だけ時間がかかる（1 GB の表で何秒かは実装の Issue で測る）
- HTML の形（Excel の書式つき）は読まない。文字列だけ
