# ADR 0028 — 新規作成は新しい窓で 1 行 × 3 列から始め、名前を付けて保存は Windows は OS の画面、X11 はパレットの欄で道筋を打つ

- 状態: 受理
- 日付: 2026-11-05（受理 2026-11-06）
- Issue: #101（GitHub）
- 影響する規則: FR-005 / FR-007 / FR-022 / ARC-007 / ARC-011 / EDIT-15 / SAVE-01・03・11 / FILE-01 / ADR 0005 / ADR 0025 / ADR 0026 / ADR 0027

## 文脈

2026-11-05 に施主が「行や列を追加できないと、新規で作れないのでは」と気づいた。行と列の足し消し（EDIT-03）は ADR 0027 で決め、画面から行と列を足し・消し・戻せるようになった（GitHub Issue #95・#99）。新しく作るには、まだ次の 2 つが無い。

- **新規作成（EDIT-15）**：今の作りは、開いたファイル（原本）があることを前提にしている。原本は読むだけで、差分を重ねて保存で置き換える（ADR 0005・0024・0025）
- **名前を付けて保存（SAVE-11）**：保存は原本と同じ道筋への置き換えだけ。新しい表には道筋が無い

今の土台は次のとおり。

- 起動の入口は、引数のファイルか、Windows はファイルを選ぶ画面（`GetOpenFileNameW`・ui-win32 の `desktop`）。X11 にはファイルを選ぶ画面が無い（引数だけ）
- 保存は store が同じフォルダの一時ファイルに書き、`rename`（Linux）・`ReplaceFileW`（Windows）で置き換える（ADR 0025）。置き換え先が無いファイルは、`rename` も `MoveFileExW` も作れる
- 1 つのプロセスが 1 つの窓・1 つのファイルを持つ。合成ルートはスレッドもプロセスも持てない（ARC-007）

## 決定

### 1. 新規作成は新しい窓で開く

- Ctrl+N とパレットの「新しい表を作る」で、自分の exe を `--new` で起こし直す（Excel・メモ帳と同じく、今の窓は残る）
- プロセスを起こすのは adapters に置く（ARC-007。Windows は `CreateProcessW`、X11 側は `std::process::Command`）
- 起動の入口（引数が無いとき）にも「新しい表を作る」を足す（Windows のファイルを選ぶ画面の前に出す）

### 2. 初めの表は 1 行 × 3 列、見出しの行は無し

- 原本の無い表を、空の原本（0 バイト）と差分（行の並びに足した行 1 つ・列の並びに足した列 3 つ）で表す。ADR 0005 の「原本 ＋ 差分」のまま、特別な経路を作らない
- 見出しの行は無し（列の番号の行を出す・Issue #48）。見出しにしたい行は、書いてから「見出しの行を選ぶ」で選ぶ
- 行と列は ADR 0027 の操作で足す

### 3. 新しいファイルの書き方は Excel で開ける形

- 文字コードは **BOM 付きの UTF-8**（BOM が無いと、日本語の Windows の Excel は Shift_JIS として読み、文字化けする）
- 区切りはカンマ、改行は CRLF、引用は要るときだけ（RFC 4180）
- 書き方を変えて書き出すのは SAVE-03（方言を変えて書き出す）で扱う

### 4. 名前を付けて保存の画面

- **Windows**：OS の保存の画面（`GetSaveFileNameW`。開く画面と同じ comdlg32 なので依存は増えない）
- **X11**：OS の画面が無いので、パレットの欄に道筋を打つ（初めの値は今のファイルのフォルダ。補完は後の Issue）
- Ctrl+Shift+S とパレットの「名前を付けて保存…」
- 新しい表（道筋の無い表）の Ctrl+S は、名前を付けて保存になる

### 5. 名前を付けて保存の書き方と、その後

- 書き方は保存と同じ経路（store の一時ファイル → 置き換え・ADR 0025）。置き換え先だけが違う
- 置き換え先に既にファイルがあれば、上書きしてよいか尋ねる（ADR 0026 の尋ねる画面と同じ作り）
- 保存の後は、窓は新しいファイルを指す（題名・保存先が替わる・Excel と同じ）。元のファイルは変えない
- 名前を付けて保存は、方言と文字コードを変えない（変えるのは SAVE-03）

## 強制

- **active**（GitHub Issue #109・#111 で入れた）:
  - 新しい表を保存すると、BOM 付きの UTF-8・CRLF・カンマで、足した行と列が方言どおりに書かれる（app のテスト `a_blank_table_is_planned_as_utf8_with_a_bom_crlf_and_commas`。原本を BOM だけの 3 バイトにしたので、保存の計画が BOM を写す）
  - 名前を付けて保存は、元のファイルのバイト列を変えない（store のテスト `saving_as_a_new_file_creates_it_and_leaves_the_original_alone`）
  - 上書きの確認を出さずに、既にあるファイルを置き換えない（application のテスト `saving_as_needs_a_second_enter_to_overwrite`・store のテスト `saving_as_a_new_file_refuses_a_file_that_appeared`。Windows は OS の画面の `OFN_OVERWRITEPROMPT` が尋ねる）
- **planned**:
  - 引数が無いときの起動の入口に「新しい表を作る」を足す（決定 1 の 3 つ目。Ctrl+N とパレットは GitHub Issue #113 で入れた）
- **不能（レビュー事項）**:
  - プロセスを起こす経路が adapters の外に無いか（ARC-007・CNF-012 で見られるかは実装の Issue で確かめる）

## 結果

得られるもの:

- 空の表から作って、Excel で開けるファイルに保存できる
- 新しい表も「空の原本 ＋ 差分」なので、保存・Undo・行と列の足し消しの経路が 1 つのまま

失うもの・残る穴（**正直に**）:

- X11 の名前を付けて保存は、道筋を手で打つ（補完とフォルダを辿る画面は後）
- 新しい窓はプロセスごとなので、窓どうしでクリップボード以外の受け渡しは無い
