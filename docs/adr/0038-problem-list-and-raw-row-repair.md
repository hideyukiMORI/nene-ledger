# ADR 0038 — 構造の検査は裏で数えてパレットの一覧に出し、壊れた行は元のバイト列を詳細ペインで直して読み直す

- 状態: 提案
- 日付: 2026-11-16
- Issue: #517（GitHub）
- 影響する規則: FR-003 / FR-005 / FR-023 / ARC-001 / ARC-011 / VALD-01 / EDIT-14 / OPEN-14・15 / ADR 0005 / ADR 0014 / ADR 0018 / ADR 0024

## 文脈

M2 の題は「壊さず直して保存する（探して置き換え、壊れた行を直す）」で、壊れた行の束が 3 項目残っている。

- VALD-01 構造の検査（列数の不一致・不正な引用符・壊れた文字）を**一覧**し、該当の行へ飛ぶ
- EDIT-14 壊れた行を**元のバイト列のまま**手で直し、読み直して列数が合うことを確かめる（ペルソナ ETL・EC「ローダーの reject を GUI で直す。見せるだけでは CLI と同じ」）
- OPEN-15 の残り（壊れた所へ飛ぶ・隔離して示す）

今あるもの（コードで確かめた）は、1 つずつ別の入口になっている。

| 壊れ方 | 今の見せ方 | 今の直し方 |
| --- | --- | --- |
| 列の数が見出しと違う行 | 行番号に注意の色と帯・状態の行に数と `F8`・F8／Shift+F8 で次／前へ（GitHub Issue #317・#338） | 余計なセルを消す（パレット・#413）・足りないセルに書く（#83） |
| 閉じない引用符 | 状態の行に「n バイト目の引用符が閉じていません（最後の行）」（#511） | 読み方を「文字として読む」に替えて開き直す（ADR 0018・#511） |
| 読めないバイト（文字コードで復号できない） | セルの中に `U+FFFD`。scan の `DecodedText::malformed` は取れるが、数えても示してもいない | 文字コードを選び直す |
| 引用符の後ろに字が続くセルなど（`a,"b"c,d`） | 何も示さない（規則どおりに読む） | — |

足りないのは、(1) 全部をまとめた一覧、(2) 行をセルに切る前の**元の 1 行**を見て直す口である。列の数が違う行は、たいてい「引用符の閉じ忘れ」「区切りの字が値に入った」で、セルごとに直すより、元の 1 行の引用符を 1 つ足すほうが早い。

## 決定

**検査は、開いたファイルの全部の行を裏で 1 回数え、種類ごとの件数をパレットの「問題の一覧」に出す。壊れた行は、詳細ペインに元の 1 行（切る前の文字列）を出して直せ、確定すると、その行だけを読み直した結果で置き換える。**

1. **検査の種類**（閉じた集合・core）：列の数が違う／閉じない引用符／読めないバイト／引用符の後ろに字が続く。索引を作り終えた後に、裏の一括処理で全部の行を 1 回読んで数える（列の数が違う行の数えは今もこうしている）。保存の後は数え直す。
2. **一覧**：パレットの「問題の一覧…」。段に種類ごとの件数を並べ（0 件の種類は出さない）、選ぶと最初の所へ飛び、F8／Shift+F8 がその種類の次／前になる。件数が 0 なら「構造の問題は見つかりませんでした」。状態の行の数（今の「列の数が違う行 n（F8）」）は、全部の種類の合計に替える。
3. **元の 1 行で直す**：パレットの「この行を元の文字のまま直す」。詳細ペインに、カーソルの行の原本の文字列（復号した 1 レコード・引用符と区切りを含む・改行は印）を出し、数式バーと同じ欄で直す（GitHub Issue #458 の作り）。確定（Enter・改行は Alt+Enter で、今の詳細ペインの欄と同じ）で、その文字列を今の方言で切り直し、行のセルを置き換える。Esc でやめる。
   - 直している間、ペインの見出しに「この行は n セル（見出しは m セル）」を出し、打つたびに数え直す（合えば注意の色が消える）
   - 切り直した結果が 2 行以上になるなら（改行を足した）、行を足す 1 手と束ねる
   - 1 手で戻る（Ctrl+Z）
4. **差分の持ち方**：直した行は「行ごと書き換えた」として持つ（その行の全部のセルの書き換え ＋ 余計なセルは「セルが無い」）。保存では、直した 1 行だけを書き、**ほかの行は原本のバイト列のまま**（FR-003）。新しい差分の種類は足さない（ADR 0024 の層 2 のまま）。
5. **閉じない引用符の行**（規則の正本では、終わりまでが 1 つのセル）は、元の 1 行が残りの全部になる（1 MiB で切り詰める）。切り詰めた行は直せない（今のセルの編集と同じ・ADR 0026 の決定 1）。この場合は、読み方を「文字として読む」に替えてから直す（ADR 0018）と案内する。
6. 文字として読んだ後の「壊れた所へ飛ぶ」ために、索引は閉じなかった引用符の**行の番号**も覚える（今はバイトの位置だけ）。

## 強制

- **planned**（受理の後の Issue で）:
  - 検査の数は、スレッドの数と塊の切り方に依らない（QLT-008 の 2・乱数の入力）
  - 元の 1 行を何も変えずに確定すると、差分が増えない
  - 元の 1 行を直して保存したファイルは、その 1 行だけが違う（QLT-008 の 3）
- **不能（レビュー事項）**: 一覧の文言が、何が壊れているかを利用者の言葉で言えているか（FR-023）

## 結果

- 得るもの：壊れ方がどれだけあるかが 1 か所で分かり、次々に飛んで、元の 1 行のまま直せる。CLI の reject の列をエディターで直す作業が、その場で読み直しまで終わる。
- 失うもの：開くたびに全部の行をもう 1 回読む（列の数えは今もしている。種類が増えても読むのは 1 回）。パレットの操作が 2 つ増える。
- 残る穴：一覧は「件数と、次へ飛ぶ」までで、壊れた行だけを集めた別の表（隔離の表）は作らない。規則（必須・長さ・選択肢）の検査は VALD-02・03（M4）。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 壊れた行だけを集めた別の表（隔離の表）を、窓の下か別の窓に出す | 部品が 1 つ増え、行の並びと 2 か所で同じ行を見せることになる（ARC-001）。飛ぶ先が分かれば、表の中で前後の行と並べて見るほうが直しやすい。要るなら M3 の絞り込み（FILT）で「問題のある行だけ」を出す |
| 元の 1 行を、セルの欄で直す | 欄は 1 つのセルの値の幅しかなく、引用符と区切りの入った 1 行は長い。詳細ペインは複数行・スクロール・押した所にカーソルが既にある |
| 元のバイト列を 16 進で見せて直す | 文字コードで復号できる行がほとんどで、利用者が直したいのは引用符と区切り。読めないバイトは文字コードの選び直しで直る。16 進は VIEW の別の項目 |
| 引用符の閉じ忘れを推し量って自動で直す | 推し量りで原本の意味を変える（ADR 0018 の却下と同じ） |

## 施主の判断（尋ねること）

1. 一覧は**パレットの段**でよいか（推し）。窓の横か下に、出したままにできる一覧の欄が要るか
2. 元の 1 行は**詳細ペイン**で直す、でよいか（推し）
3. 「引用符の後ろに字が続くセル」も問題として数えるか（推し：数える。Excel が書き出さない形で、たいてい手で書いた閉じ忘れ）
4. 壊れた行だけを集めた表（隔離の表）は作らない、でよいか（推し）
