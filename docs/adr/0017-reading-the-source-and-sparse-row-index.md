# ADR 0017 — 原本は位置を指定した読み出しで塊ごとに読み、行の索引はまばらな目印（1,024 行ごと）で持つ。写像は測ってから

- 状態: 受理
- 日付: 2026-10-22
- Issue: #8
- 影響する規則: ARC-004 / ARC-005 / ARC-007 / RS-010 / QLT-008 / QLT-014 / CNF-015。FR-004・BIG-01〜04・ADR 0005 / 0006 / 0014

## 文脈

ADR 0006 の決定 6 は「写像（mmap）は危険への備えを決めてから製品の経路に入れる。それまでの既定は安全な読み出し」とした。
行の索引で各行の位置を全部持つと、1 億行で 800 MB（`u64` × 1 億）になり、「メモリはファイルの大きさでなく索引と差分に比例」（BIG-04）を破る。
Windows で原本を開いたまま保持すると、Excel などが同じファイルを保存（置き換え）できなくなる恐れがある（FR-019）。

## 決定

**原本は、位置を指定した読み出し（Linux は `pread`、Windows は `ReadFile` の位置指定）で、決まった大きさの塊ごとに読む。行の索引は、1,024 行ごとの目印（その行が始まるバイト位置）だけを持つまばらな表にし、目印の間は読むたびに切り直す。写像は、ADR 0006 の危険を測ってから別の ADR で入れる。**

1. **塊の読み出し**: 塊の大きさは決め打ちしない（初期値 1 MiB）。最近読んだ塊を数個だけ記憶に残す（上限つき）。画面に見えている所の塊を先に読む
2. **まばらな索引**: 目印は「レコードの始まり」に置く（引用符の中の改行で切らない）。1 億行で目印は約 10 万個・約 0.8 MB。ある行へ飛ぶときは、その前の目印から最大 1,023 行を切る（参照実装か速い経路・ADR 0006）
3. **索引の作り方**: 先頭から裏で作る（ADR 0014）。作り終わる前でも、作り終えた範囲は飛べる（BIG-02）。並列に作るときは、塊の境目が引用符の中か外かの両方を仮に計算して後で突き合わせる（ADR 0006 の決定 4）
4. **開き方**: 読むだけで開く。Windows では共有の指定を「読み・書き・削除を他に許す」にして、他のアプリの保存を妨げない（その代わり外部の変更を検出する・FR-019）。scan は書き込みの API を使わない（CNF-015）
5. **行の番号**: 物理的な行（改行の数）ではなくレコードの番号で数える（VIEW-16 は両方を出す）
6. **写像を入れる条件**: (a) 読み出しとの速さの差を、ページキャッシュに載っている・載っていない・ネットワーク共有の上で測る（QLT-014）(b) Linux の SIGBUS（他のプロセスがファイルを縮める）の扱いを決める (c) Windows で写像が他のアプリの保存を妨げる問題の扱いを決める。3 つがそろったら ADR を立てる

## 強制

- **active（既存）**: CNF-015（scan は書き込みの API を使わない）・CNF-012（ファイルを読むのは scan・store・adapters だけ）
- **planned**: 索引の目印から切った結果と、先頭から全部切った結果が同じになるテスト（QLT-008 の 1・2）。索引のメモリの実測（BIG-04・QLT-014）

## 結果

- 得るもの: メモリが行数にほぼ比例しない（目印 1,024 行ごと）。写像の SIGBUS もロックの問題も最初は持たない
- 失うもの: 任意の行へ飛ぶたびに最大 1,023 行を切る手間。速い経路（SIMD）で十分速いかを測る
- 残る穴: 読み出しはシステムコールが写像より多い。巨大なファイルの全体の走査（検索・集計）で差が出るかもしれない。測ってから写像を判断する

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 全行の位置を持つ密な索引 | 1 億行で 800 MB。BIG-04 を破る |
| 最初から写像（mmap） | ADR 0006 の危険（SIGBUS・保存の妨げ）を測る前に入れることになる |
| 全体を記憶に読み込む | 巨大なファイルで最初の画面が出ない（BIG-01） |
| 目印を固定のバイト間隔（例: 1 MiB ごと）に置く | 行の番号から飛べない。行の番号で間隔を決める |
