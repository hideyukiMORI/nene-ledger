# ADR 0024 — 差分は「行の並び」と「セルの書き換え」の 2 つの層で、原本のレコードの番号に重ねて持つ

- 状態: 受理
- 日付: 2026-11-05
- Issue: #53（GitHub）
- 影響する規則: FR-003 / FR-005 / FR-006 / FR-004 / ARC-001 / ARC-004 / ARC-011 / KEEP-02〜05・07 / EDIT-01〜04・10 / UNDO-01 / BIG-12 / BIG-13 / ADR 0005 / ADR 0017

## 文脈

[ADR 0005](0005-source-is-read-only-until-save.md) は、次の 2 つを決めた。

- 編集は、原本の位置（行の番号・列の番号）に対する差分として application が持つ
- 保存では、触っていない行を原本のバイト列のまま写す。編集した行でも、触っていないセルは元のバイト列を写すことを目標にする

差分の形は「実装の Issue で測って決める」と残してあった。M2 の最初の縦切り（EDIT-01・SAVE-01・KEEP-02・03：1 セルの書き換え → 保存 → 往復のバイト一致）の前に、次の 5 つを決める必要がある。

1. 行と列を何で指すか。並べ替え（M3）・行の挿入と削除・Undo のあとでも、同じ行を指し続けられること
2. 差分の型をどこに置くか。core は `#![no_std]` の純粋な規則、application は開いたファイルの状態の持ち主
3. 編集したセルを、保存でどう書くか。引用・改行・文字コード
4. 索引を作り終える前に編集できるか（BIG-12）。今の索引は、1,024 行ごとのまばらな目印を裏で作る（ADR 0017）
5. 記憶が、ファイルではなく差分の大きさに比例すること（BIG-13）

使える土台は次のとおり。

- core の `Record` は、原本の区間（`raw`）・終わり方（`terminator`）・セルの位置（`fields`）を持つ。`raw` と `terminator` をつなげると原本のバイト列に戻る
- 範囲の取り出し（scan の `read_records`）は、窓のレコードを原本の位置（`offset`）と全体の長さ（`length`）と一緒に返す。索引を作り終える前でも、レコードの番号は目印からの数で決まる

## 決定

**差分は 2 つの層で持つ。層 1 は「行の並び」（原本のレコードの番号の区間と、足した行の列）、層 2 は「セルの書き換え」（行と列の同一性から値への写像）。型と規則は core に置き、開いたファイルごとの持ち主と Undo の束は application に置く。**

### 1. 行と列は、位置ではなく「同一性」で指す

- 行の同一性 `RowId` は 2 通り。原本のレコード `Source(n)`（`n` は原本の中のレコードの番号。前書きと見出しも数える）と、足した行 `Added(k)`（開いている間に配る通し番号）
- 列の同一性 `ColumnId` も 2 通り。原本の列 `Source(c)`（原本の中のセルの番号）と、足した列 `Added(k)`
- 画面の行の番号と列の番号は、層 1 から計算する派生値にとどめる。差分と Undo の記録には `RowId` と `ColumnId` を使う

これで、並べ替え（表の見え）・行の挿入と削除・Undo のあとでも、書き換えたセルは同じ行と列に付いたままになる。

### 2. 層 1：行の並びは区間の列（piece table）

```text
RowOrder = [Piece]
Piece    = SourceRun { first: n, count: N | 終わりまで }  // 原本の連続した行
         | AddedRows [Added(k)…]                          // 足した行
```

- 開いた直後は、`SourceRun { first: 0, count: 終わりまで }` の 1 つだけ。索引を作り終える前でも表せる（BIG-12）
- 行の削除・挿入・移動は、区間を割って並べ替えるだけで、原本は読まない。1 億行のうち 100 万行を消しても、区間が 1 つ増えるだけ
- 画面の行 → `RowId` の引き当ては、区間の長さの累積を二分探索する。区間の数は編集の回数に比例する（BIG-13）
- 列の並び（`ColumnOrder`）も同じ形で持つ。列の挿入・削除・移動・見出しの名前の変更（EDIT-03・04）は、列の並びと層 2 で表す

### 3. 層 2：セルの書き換えは疎な写像

```text
CellEdits = Map<(RowId, ColumnId), CellValue>
CellValue = Text(String)   // 利用者が入れた値（引用を外した文字列。改行を含んでよい）
          | Absent         // 「セルが無い」（KEEP-05）。消したセル・足した列の触っていない所
```

- 値は文字列で持ち、型を推測しない（ADR 0005 の 5）。数や日付として見るのは、比較の規則と変換の規則の側だけ
- 「空のセル」は `Text("")`、「セルが無い」は `Absent`。この 2 つを区別して保つ（KEEP-05）
- 足した行のセルは、すべて層 2 に入る。原本のセルの値は、原本から読む（写さない）

### 4. 保存で行をどう書くか（store の書き方の規則は ADR 0025）

core に、行ごとの書き方を 3 つに分ける純関数を置く。

| 行の状態 | 書き方 |
| --- | --- |
| 層 1 でも層 2 でも触っていない原本の行 | 原本のバイト列（`raw` ＋ `terminator`）をそのまま写す。続いた行はまとめて 1 つの区間として写す |
| 原本の行で、セルを書き換えた | 書き換えていないセルは、原本のセルのバイト列（引用符を含む）をそのまま写す。区切りは方言の区切り、終わり方は原本のその行の `terminator` |
| 足した行・列の構造が変わった行 | 方言どおりに書く（`csv_writing` の規則） |

**編集したセルの引用（施主の判断 1）**は、原本のそのセルが引用されていたら引用したまま書く。引用されていなければ、要るとき（区切り・引用符・改行を含むとき）だけ引用する。引用符の逃がし方は方言の `quote_escape` に従う。

- これで、全項目を `"` で囲んだ日本の業務の表（JP-05）は、編集しても囲みのまま残る
- 「引用しない値」を引用してから元に戻すと、元のバイト列には戻らない。値が同じでも、バイトの一致は約束しない
- セルが 1 つの行を空にするときは、引用の方言なら `""` と書く。空の行にすると、前の行が `\r` で終わっていれば `\r\n` につながって行が 1 つ消える（GitHub Issue #56 のランダムの往復のテストで見つけた）。空の行を読み飛ばす読み手もある。`Plain` と `Backslash` の方言では引用できないので、この穴は残る

セルの中の改行（EDIT-10）は、利用者が入れたとおりに `\n` で持つ。保存で、その行の `terminator` の改行（`\r\n` など）に揃える（**施主の判断 2**）。

### 5. Undo は差分への操作の列

- 編集の 1 手は `EditStep` で表す。差分への操作（区間の割りと並べ替え、写像への出し入れ）と、その逆の操作の組
- 一括の操作（複数のセルへの入力・置換・貼り付け）は、`EditStep` の束を 1 手にする（UNDO-01）
- 開いている間は数を限らない（FR-006）。記憶は、手の数と、1 手で書き換えたセルの数に比例する
- Undo / Redo は application の `Document` が持つ。UI は意図（「元に戻す」）を渡すだけ（ARC-011）

### 6. 型と規則は core、持ち主は application

- core に置くもの：`RowId`・`ColumnId`・`RowOrder`・`ColumnOrder`・`CellEdits`・`CellValue`・`EditStep`・行の書き方の判定・画面の行から `RowId` への引き当て。どれも純関数で、`alloc` だけを使う
- application に置くもの：開いたファイルごとの差分と Undo の束。表示のフレームを作るときに、範囲の取り出しの結果へ差分を重ねること
- 画面の表は、原本 ＋ 差分から作る派生値にとどめ、正本にしない（ADR 0005）

### 7. 索引を作り終える前の編集（BIG-12）

- 層 1 の最後の区間は「終わりまで」のまま持つ。行の数が分からなくても、見えている行の前後を割れる
- 層 2 は、見えている行の `RowId`（`Source(n)`）で持つ。`n` は目印からの数なので、索引の完成を待たない
- 「最後の行の後ろに足す」・「全体の行の数に依る操作」（末尾から数える・全体の置換）は、索引ができるまで待つ（裏の処理の進み具合を示す・ADR 0014）

## 強制

- **planned（最初の縦切りの Issue で active にする）**:
  - 何も触らずに保存したら、ファイルがバイト単位で同じになる（KEEP-02）。core の行の書き方の判定が、全部の行を「原本を写す」にすることを、テストで固める
  - 書き換えた行の、触っていないセルのバイト列が同じになる（KEEP-03）。core のテストと、実ファイルでの往復で固める
  - 差分の操作と逆の操作が組になること。操作の列を無作為に作り、進めて戻すと元の差分に戻るテストで固める（UNDO-01）
- **不能（レビュー事項）**:
  - UI が表示用の複製を正本にしていないか（ARC-011）

## 結果

得られるもの:

- 1 億行のファイルでも、編集の記憶は差分に比例する（BIG-13）。行の削除や移動で、原本を読むことは無い
- 並べ替え・削除・Undo のあとでも、書き換えたセルは同じ行と列に付いたまま
- 保存の書き方の大半（触っていない行を写すこと）が core の純関数で決まり、ファイル無しでテストできる

失うもの・残る穴（**正直に**）:

- 🔴 **原本が外から変わると、`Source(n)` の意味が変わる。** 保存の前に確かめて止める（ADR 0025）。開いている間に変わったことを示す経路（FR-019）は、別の ADR で決める
- 🔴 **画面の 1 行を引き当てるのに、区間の二分探索が要る。** 区間が数十万になる編集（1 行おきの削除など）での速さは、最初の縦切りで測る
- 列の数が行ごとに違うファイル（OPEN-14）で列を挿入すると、短い行には新しい列の前の位置にセルが無いことがある。その行は「構造が変わった行」として方言どおりに書く。原本のバイト列は写さない
- 変換の規則（XFRM・M3）は、この 2 つの層の上に重ねる 3 つ目の層にする。ここでは決めない

## 施主の判断（2026-11-05・GitHub Issue #53）

下の表の推しを、すべて受理した。

1. 編集したセルの引用: 原本のセルが引用されていたら引用のまま。それ以外は要るときだけ
2. セルの中の改行の保存: その行の `terminator` に揃える
3. 型の置き場: core に型と規則、application に持ち主と Undo の束

### 追加の判断（2026-11-05・GitHub Issue #83）

施主が Windows の実機で、列の数が足りない行（OPEN-14）の「セルが無い」所に書けないことに気づいた（gate-proofs 第 61 節）。推しのとおり、2 つを受理した。

4. **セルの無い所にも書ける。** 打ち始め・F2・IME の確定で、見えている値は空として編集に入る。空のまま確定したら差分にしない（ファイルの値と同じ）。差分で消したセル（`Absent`）は今までどおり直さない
5. **間の列は「空のセル」で埋める。** `a,b` の 4 列目に `x` と書くと `a,b,,x` になる。書いた行は「構造が変わった行」になり、その行の「セルが無い」所が減る（KEEP-05 の例外）。原本の行の終わり（終わり方の前）までは原本のバイト列を写し、終わり方も原本のまま。触っていない行はバイト列のまま（FR-003）

| # | 問い | 推し | ほかの案 |
| --- | --- | --- | --- |
| 4 | セルの無い所に書けるか | 書ける（Excel 育ちの人は書けると思って打つ） | 書けない（止めると戸惑う・列を足す操作 EDIT-03 を待つ） |
| 5 | 間の列 | 空のセルで埋める | 間を飛ばして後ろだけ置く（CSV の形の上、書き方が無い） |

### 判断の前に並べた選択肢

| # | 問い | 推し | ほかの案 |
| --- | --- | --- | --- |
| 1 | 編集したセルの引用 | 原本のセルが引用されていたら引用のまま。それ以外は要るときだけ | 常に要るときだけ（JP-05 の表が囲みを失う）／常に引用する（触っていないセルと見た目が揃わない） |
| 2 | セルの中の改行の保存 | その行の `terminator` に揃える | 常に `\n`（Excel で `\r\n` の表に `\n` が混じる）／入れたとおり（入力の経路で改行が変わる） |
| 3 | 型の置き場 | core に型と規則、application に持ち主 | application にすべて（core の純関数のテストの利点を失う） |

## 追記（2026-11-09・GitHub Issue #413）：行の後ろの余計なセルを消す（提案・施主の確認待ち）

業界のペルソナ（データエンジニア）の相談：「列の数が多い壊れた行の余計なセルを消す道が無い。数えて飛べるようになった今、その場で直せないのが取り込み前の最後の穴」（`docs/research/2026-11-09-industry-personas.md`）。決定 1 で「セルが無い」（`Absent`）を「消したセル」にも使うと決めていたが、原本のセルを `Absent` にした行の書き方は無かった（保存は `Unsupported` で止めていた）。

1. **消せるのは、見出しより後ろの、行の終わりまで続くセルだけ。** パレットの「この行の見出しより後ろのセルを消す」（`TrimExtraCells`・漢字の「余計なセル」「壊れた行」でも引ける）が、カーソルの行の見出しのセルの数より後ろを全部 `Absent` にする。1 手で戻せる（`EditStep::Trim`）。途中のセルを消す・1 列目から消すことはしない
2. **保存は、残すセルまでを原本のまま写し、終わり方を原本のまま付ける**（core `trimmed_row`）。消す所が行の終わりまで続かない・消した所より右を書き換えている差分は、今までどおり `Unsupported` で止める
3. **見出しの無い表・列を足し消しした表では消さない**（比べる列の数が無い）。消した後は、行番号の注意の印・詳細ペインの「列の数が違う」を、消した後の数で判じる（`CellEdits::kept_width`）
4. **消す手は、保存の後に履歴を残さない**（行の足し消しと同じ。保存で原本の列の番号が変わる）
5. 詳細ペインは、見出しより多い行を「121 行目（6 列・見出しは 5 列 · Ctrl+Shift+P「余計なセル」で消せる）」と言う

キーは割り当てない（Ctrl+- を余ったセルで別の意味にすると、行を消すと取り違える）。足りないセルを足すのは今までどおり、セルの無い所に書けばよい（判断 4・5）。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 差分を「画面の行の番号 → 値」で持つ | 並べ替え・行の挿入と削除のたびに、全部の差分の番号を付け直すことになる。Undo の記録も壊れる |
| 書き換えた行を、行の文字列（またはバイト列）まるごとで持つ | 触っていないセルのバイト列を保つ（KEEP-03）ために、もう一度切ることになる。1 セルの書き換えで行の全部を写す。列の操作と組み合わない |
| 開いたときに全部の行に `RowId` を振った配列を作る | 1 億行で 800 MB。記憶がファイルに比例する（BIG-13 に反する） |
| 編集のたびに、新しい内容を一時ファイルに書き出す | 保存の置き換え（ADR 0005 の 6）と別の書き込みの経路ができる（ARC-001）。1 セルの編集で巨大な書き込みになる |
| Undo を、差分の全体の写し（スナップショット）で持つ | 記憶が、手の数 × 差分の大きさになる。一括の置換を数回で記憶が尽きる |
