# ADR 0022 — 計算は値に対して行い、数式を保存も評価もしない

- 状態: 受理
- 日付: 2026-11-05
- Issue: #8（GitHub）
- 影響する規則: FR-003 / FR-012 / FR-031（SEC-01）/ KEEP-01 / STAT-09 / XFRM-17

## 文脈

施主（2026-11-05）: 「最終的には Excel の表計算の基本関数だけで数値計算ができるパレット」が欲しい。
一方で SPECIFICATION 第 3 節は「数式」を非要件とし、SEC-01 は「数式を一切評価しない」と約束している（CSV インジェクションの入口を作らない・OWASP）。

業務ペルソナ 5 人（経理・EC・データアナリスト・ETL・人事名簿）に尋ねた結果（`_work/reports/2026-11-05-nene-ledger-persona-needs.md`）、5 人とも「セルに式を保存せず、選んだ範囲に関数を当てて値として見せる・貼るなら両立する」と判断した。要る関数の和集合は SUM・AVERAGE・COUNT・COUNTA・COUNTBLANK・MIN・MAX・MEDIAN・一意の数・ROUND（四捨五入／切り捨て／切り上げ）・LEN / LENB と、列 × 定数・列 ± 列の上書き。

## 決定

1. **セルは値だけ。** セルに `=` で始まる式を書いても、それは文字列であり、評価しない（SEC-01 のまま）。数式に見えるセルの強調と無害化（SEC-02 / 03）も変えない
2. **計算は「選んだ範囲か列」に対する操作**で、結果は値として状態の行か結果の欄に出す。貼るときは文字列の値として差分に入る（KEEP-01・FR-003）。式そのものはどこにも残らない。再計算されない
3. **2 つの入口に分ける。** 集計（範囲 → 1 つの値。STAT-09・FR-012）と、列の演算（列 → 新しい列か上書き。XFRM-17・FR-011・変換の規則の一種でプレビューと件数を出す・XFRM-01）
4. **数の読み方は利用者が選ぶ見方のまま**（KEEP-08）。数として読めなかったセルの件数を結果と一緒に必ず出す（SORT-03 と同じ思想）。概算は使わない
5. 関数は閉じた `enum`（RS-002）で、名前は Excel と同じ英語の綴り。表示名は表示言語の表（ADR 0011）。足すときはこの ADR の表に 1 行足す
6. 計算は core の純関数（10 進で正確に・Issue #42 の `Decimal`）。巨大な範囲は裏で（Issue #43 の `RangeJob` の経路）。外部のプログラム・ネットワークは使わない（SEC-05）

## 強制

- **active**: `unsafe_code` / 外部依存の許可制（ARC-013）/ CNF-012（計算の経路が時刻・環境を読まない）
- **planned**: 「式を保存しない」はレビュー事項（差分の層に文字列以外が入らないことを型で縛る案は差分の ADR で決める）

## 結果

得られるもの: 施主の構想（基本関数だけの計算）を、CSV インジェクションの入口を作らずに入れられる。STAT-01 と同じエンジンの別の入口なので、列の要約と実装を共有できる。

失うもの: セル間の参照・再計算・式の保存（表計算ソフトの中核）は無い。それは表計算ソフトの仕事で、本製品の約束の外（SPECIFICATION 第 3 節）。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| セルに式を書いて評価する（表計算） | SEC-01 と FR-003 に反する。保存したファイルを他の道具が開いたときに式が文字列として残る |
| 計算を外部のエンジン（DuckDB の SQL）に任せる | ADR 0007。依存の許可制と SEC-05 |
| 関数を利用者が定義できるようにする（スクリプト） | AUTO-07（やらない） |
