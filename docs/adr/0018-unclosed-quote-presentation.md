# ADR 0018 — 閉じない引用符は、規則の正本を厳格に保ったまま位置を示し、「その引用符を文字として読む」を利用者が選べる別の規則にする

- 状態: 受理
- 日付: 2026-10-23
- Issue: #13（提案）・#14（受理）
- 影響する規則: ARC-001 / ARC-009 / RS-002 / RS-004 / QLT-008 / FR-003 / FR-023。OPEN-15・BIG-04・ADR 0005 / 0006 / 0017

## 文脈

規則の正本（core の参照実装・RFC 4180 の読み方）では、閉じない引用符から入力の終わりまでが 1 つのセルになり、そのレコードは `RowShape::UnclosedQuote` になる。
引用符が閉じないことは、入力の終わりまで読んで初めて確定する。途中の時点では「とても長い引用の中のセル」と区別できない。

Issue #13 で、索引と範囲の取り出しの記憶はレコードの大きさに依らなくなった（256 MiB の閉じない引用符で、最大の常駐メモリ 265,576 KB → 3,784 KB）。残るのは見せ方である。

- 画面には、ファイルの残り全部を含む 1 行が出る。範囲の取り出しは先頭 1 MiB だけを返す（`WindowRecord::is_truncated`）
- 利用者は、どこで壊れたかが分からない。経理の利用者はファイルを開けること自体を求める（[討議](../research/2026-10-23-unclosed-quote-memory.md) ④）

他の製品は、厳格に誤りにする（DuckDB の既定・`csv` の上限）か、緩めた読み方を設定で選ばせる（DuckDB の `strict_mode = false`・univocity・EmEditor のセル内の最大改行数）。

## 決定

**規則の正本は厳格なまま（入力の終わりまでが 1 つのセル）。索引は閉じなかった引用符の位置を覚え、画面はその位置を示す。読み直しは、利用者が選ぶ別の規則「閉じない引用符を文字として読む」として core に置き、方言の設定として版を付けて残す。**

1. **検出**: 索引は、入力の終わりで引用の中にいたら、そのレコードの番号と、閉じなかった引用符のバイト位置を覚える（記憶は一定）。索引を作る途中で、引用の中のセルが 1 MiB（範囲の取り出しの上限 `RECORD_READ_LIMIT` と同じ値）を超えたら、「閉じない引用符かもしれない」と途中で知らせる（読み方は変えない）
2. **表示**: 壊れた行は「引用符が閉じていない（何行目・何バイト目）」と示し、そこへ飛べる（OPEN-15・FR-023）。切り詰めた行は、切り詰めたことと全体の大きさを示す
3. **読み直し（利用者が選ぶ）**: 方言の設定に閉じた集合 `UnclosedQuote { ToEnd, Literal }` を足す。既定は `ToEnd`（正本）。閉じない引用符を見つけたら、`Literal` で読み直すかを利用者に尋ねる（黙って読み直さない）。`Literal` は、閉じなかった引用符で始まったセルを引用の無いセルとして読み（引用符は文字）、その後ろは普通に切る。規則は core の参照実装に足し、scan の状態機械はそれと同じ結果を出すことをテストで固定する（ADR 0006）
4. **読み直しの手間**: 閉じなかった引用符の位置から先だけを位置指定の読み出しで切り直す。記憶は一定。読み直した後ろで別の引用符がまた閉じなければ、同じことを繰り返す
5. **保存**: どちらの規則でも、触っていない行はバイト列のまま書き戻す（FR-003・ADR 0005）。読み方を変えただけで原本は変えない
6. 設定は版付き（ARC-009）。開き直したときに同じ読み方を再現できる

## 施主の判断（2026-10-23・Issue #14）

Issue #13 で提案として置き、次の 3 点を施主に尋ね、3 点とも提案どおりとなった。

1. 既定は `ToEnd`（厳格）。閉じない引用符を見つけたら、`Literal` で読み直すかを尋ねる
2. 途中で知らせる目安は、引用の中のセルが 1 MiB を超えたとき（バイトの大きさで見る。改行の少ない巨大なセルも捕まえられ、範囲の取り出しの上限と同じ値で 1 つに揃う）
3. EmEditor の「セル内の最大改行数」のような、読み方を変える上限は初版に入れず、フェーズ 2 で検討する

## 強制

- **planned**: `Literal` の規則と状態機械の一致のテスト（乱数の入力 × 方言・QLT-008）。読み直した後も触っていない行のバイト一致（QLT-008 の 3）
- **不能**: 「読み方を黙って変えていないか」はレビュー事項（FR-023）

## 結果

- 得るもの: 壊れたファイルでも記憶が一定のまま開け、どこが壊れたかが分かり、利用者の選択で読める表になる。正本の規則は 1 つのまま（ARC-001）
- 失うもの: 方言の設定が 1 つ増える。読み直しは入力の終わりまで読んだ後なので、巨大なファイルでは待つ
- 残る穴: 閉じない引用符が何個もあると、読み直しを繰り返す（最悪は引用符の数 × 残りの長さ）。`Literal` で読んだ結果が、作った人の意図と合う保証は無い（推し量りにすぎない）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| セルの長さの上限で誤りにして開かない（Python の `csv`） | 開けないのは利用者の求めに反する。上限は対症療法で、作りとして記憶を抑えれば要らない（討議 ⑤） |
| 既定で読み方を緩める（univocity の既定・DuckDB の `strict_mode = false` を既定に） | 黙って読み方を変えることになる（FR-023）。正本の規則が 2 つになる |
| セル内の改行の数の上限で、既定から読み方を変える（EmEditor） | 上限を超える正しいセル（長い住所・備考）を壊して見せる。設定として選べるかはフェーズ 2 で検討 |
| 引用符の前後の並びから、閉じ忘れた位置を推し量って自動で直す（Ge ほかの推し量り） | 推し量りで原本の意味を変えることになる。位置を示す手がかりとしてだけ使う余地はある |
