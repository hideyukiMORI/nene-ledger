## 1. 正しく読めた率 — Pollock（Issue #24・2026-10-23）

### 測り方

[Pollock](https://github.com/HPI-Information-Systems/Pollock)（Vitagliano ほか・PVLDB 16(8)・MIT ライセンス）の汚した CSV 2,290 ファイルを読み、正しい版と見出し・レコード・セルの一致（適合率・再現率・F1）と、読み込みの成功で採点する。採点は Pollock の `evaluate.py` をそのまま使う（10 点満点。「単純」は 10 の指標の平均の和、「重み付き」はファイルの難しさの重み）。

1. Pollock を取得し（リポジトリの外に置く）、`evaluate.py` の依存を Python の仮想環境に入れる（pandas・numpy・joblib・pqdm・python-dotenv・multiset・chardet・python-dateutil・price-parser）
2. `make bench-pollock POLLOCK=<Pollock の置き場>`。release の `nene-ledger --dump <file>` を全ファイルにかけ、`results/nene/polluted_files/loading/<file>_converted.csv` と `nene_time.csv` を書く。`--dump` は窓と同じ経路（文字コードと方言の判別・索引・範囲の取り出し・復号）で読み、RFC 4180 の UTF-8 で書く。開けない組は `Application Error`
3. `python evaluate.py --sut nene`。🔴 pandas 3 では、集計の表示（存在しない道具の名前 `duckdbparse` / `duckdbauto` を引く所）で落ちる。その 1 行だけを「存在する道具だけを引く」に替えた写しで走らせた。採点の計算は変えていない

### 採点の環境の再現

Pollock のリポジトリには他の道具の読み込みの出力が入っていない（ファイルごとの採点の表だけ）。Pollock の Python `csv` の道具（`sut/pycsv`・置き場のパスだけを替えた写し）を手元で走らせて出力を作り直し、上の環境で採点すると、2,290 ファイル全部で公表の採点と一致した（差のあるファイル 0・単純 9.7211）。

### Issue #25 の後（前書きの行・2026-10-23）

同じ環境・同じ手順で測り直した。

| | 単純 | 重み付き | 重み付きの順位 |
| --- | --- | --- | --- |
| Issue #24 | 9.9489 | 9.4655 | 3 位 |
| Issue #25 | **9.9502** | **9.6601** | **2 位**（sieve 9.9922 の次・Excel 9.5972 の上） |

点が変わったファイル（ファイルごとの 10 の指標の和）:

| ファイル | Issue #24 | Issue #25 | 理由 |
| --- | --- | --- | --- |
| `file_preamble.csv` | 6.93 | 10.00 | 前書きの 2 行を判じて、`--dump` で飛ばした |
| `row_field_delimiter_0_0x20.csv` | 6.98 | 6.96 | 見出しの行の区切りが空白で 1 つのセルになり、区切りの無い表題の行と見分けられず前書きとみなした（承知の上） |

🔴 最初の判じ方（中身のあるセルが半分に満たない行は全部前書き）では、迷子の引用符で汚れた見出しを持つ `row_extra_quote0_col0` / `col1` も前書きとみなして見出しを捨て、8.53 / 8.21 → 6.96 に下がった。前書きは「セルの数がちょうど列の数か、1 つ以下」に限って、元に戻した。

### Issue #60 の後（閉じた引用符の後ろに続く文字の減点・2026-11-02）

同じ環境・同じ手順で、直す前（`main` の Issue #59 の統合）と直した後を続けて測った。直す前は Issue #25 の値と一致した。

| | 単純 | 重み付き |
| --- | --- | --- |
| 直す前 | 9.9502 | 9.6601 |
| Issue #60 | 9.9502 | 9.6601 |

点が変わったファイルは 0（2,290 ファイルの 10 の指標の和を突き合わせた）。Pollock で `\"` を使うのは `file_escape_char_0x5C.csv` だけで、引用の中にカンマがあるので直す前から `\"` の流派で読めていた（`Round 48\"` が `Round 48"` になる）。この変更が効くのは、引用の中に区切りの無いファイル（core のテスト `backslash_escapes_without_delimiters_inside_quotes_are_detected`）。
