# 調査: CSV / TSV の規格・落とし穴・研究

> Issue #3 / 2026-10-22。Web の文献調査（WebSearch / WebFetch）の記録。【要確認】は、元の文書を開いて確かめていない項目。
> 一覧への反映は [機能の一覧](2026-10-22-feature-catalog.md)。

## 1. 規格と、エディターが対応すべきこと

### RFC 4180（Shafranovich, 2005）

- 分類は Informational で、標準（Standards Track）ではない。`text/csv` の MIME タイプを登録した文書。任意のパラメータに `charset` と `header=present|absent` がある
- 規則: 行の区切りは CRLF・見出しの行は任意・全レコードのフィールド数をそろえる・`"` `,` CR / LF を含むフィールドは `"` で囲む・中の `"` は `""`・最終行の改行は任意・既定の文字コードは US-ASCII
- 改訂案 draft-shafranovich-rfc4180-bis-07（期限切れ・効力なし）は現実を追認している: 既定の charset を UTF-8・単独の CR / LF も改行として受け付けてよい・`#` で始まるコメント行（複数行のフィールドの続きと混同しない注意つき）・BOM を読めないアプリへの警告・列数の一致は推奨どまり・空行の許容・Security Considerations に CSV インジェクション。最終行の改行が MUST になったという要約がある【要確認】
- 示唆: **読むときは寛容に**（CR / LF / CRLF の混在・行ごとに違う列数・BOM・最終行の改行なし）、**書くときは厳密に**

### IANA text/tab-separated-values

- 1 行 1 レコード、タブ区切り、1 行目は見出し、全レコードの列数は同じ。フィールドにタブを含めることは禁止。引用符によるエスケープの仕組みも改行も無い（米国議会図書館の解説）
- 実際の TSV には 3 つの流派がある: CSV と同じ引用符（Excel の「テキスト（タブ区切り）」）・バックスラッシュのエスケープ（`\t` `\n` `\\`。PostgreSQL の COPY TEXT・MySQL）・エスケープなし
- 示唆: TSV の読み書きで 3 つの流派を選べるようにする

### W3C CSV on the Web（CSVW・2015-12-17 勧告）

- 文書: Model for Tabular Data and Metadata on the Web（Tennison, Kellogg）・Metadata Vocabulary for Tabular Data・Primer
- 表 → 列 → 行 → セル。セルは「文字列の値」と「型付きの値」を区別する
- 方言の記述: `commentPrefix` / `delimiter` / `doubleQuote` / `encoding` / `header` / `headerRowCount` / `lineTerminators` / `quoteChar` / `skipBlankRows` / `skipColumns` / `skipRows` / `skipInitialSpace` / `trim`。メタデータ → 表グループの方言 → 既定値の順に決まり、既定値は HTTP の Content-Type で上書きされる
- 列の記述（`tableSchema`）: `datatype` / `format` / `null` / `required` / `primaryKey` / 外部キー
- 示唆: 推し量った方言・見出しを CSVW の JSON メタデータ（`file.csv-metadata.json`）として保存・再利用すれば相互運用できる

### Frictionless Data Table Dialect / Table Schema（Data Package v2）

- Table Dialect: `header=true` / `headerRows=[1]` / `headerJoin` / `commentRows` / `commentChar` / `delimiter=","` / `lineTerminator="\r\n"` / `quoteChar='"'` / `doubleQuote=true` / `escapeChar`（`quoteChar` と排他）/ `nullSequence` / `skipInitialSpace=false`
- Table Schema: `fields`（name / type / format / constraints）・`missingValues`・`primaryKey`・`foreignKeys`
- 示唆: 方言の設定画面の項目をこれにそろえると、書き出しが容易

## 2. 落とし穴（例と、勧める振る舞い）

| # | 落とし穴 | 例 | 勧める振る舞い |
| --- | --- | --- | --- |
| 1 | 区切り文字の多様さ | `,` `;` タブ `\|` `^`・連続する空白。欧州は小数点がカンマなのでセミコロン | 判別し、候補と確信度を示す。すぐ上書きでき、ファイルごとに覚える |
| 2 | 小数点のカンマ | `"1,5";"2,75"`・`1.234,56` | 数としての解釈はロケールの設定に従う。書き出しで区切りと衝突したら警告 |
| 3 | 引用符の流派 | `""` と `\"`・シングルクォート・引用符なし | `doubleQuote` と `escapeChar` を別々に推し量り、設定できる。保存で読んだ流派を保つ |
| 4 | 引用符の中の改行 | `1,"東京都\n千代田区",x` | 物理的な行ではなくレコードで扱う。セルの中の改行を `↵` などで見せ、行の高さを調整 |
| 5 | 改行の混在 | 一部の行だけ LF・単独の CR | 全部受け付け、元の改行を保つ。混在を報告し、保存で統一を選べる |
| 6 | 列数が不ぞろいの行 | 行ごとに列数が違う | 「空」と「セルが無い」を区別して往復で保つ。列数の異常を一覧で示す |
| 7 | 末尾の区切り | `a,b,c,` | 空の最終列として扱い、往復で増減させない |
| 8 | 見出しの重複・空 | `name,,name,Unnamed` | 内部は列の番号で持ち、表示名の重複を許す。警告はするが勝手に改名しない |
| 9 | 見出しの有無・複数行の見出し | 冒頭のタイトル行・2 段の見出し | 見出しの行数と読み飛ばす行数を指定できる（`headerRows` / `skipRows`） |
| 10 | コメント行 | `# generated by ...` | `commentChar` を設定でき、既定は無効。データの `#` を捨てない |
| 11 | BOM | UTF-8 の BOM が 1 列目の名前に混ざり `﻿id` になる | 検出して外して表示し、有無を保つ。保存で有無を明示して選ぶ（Excel 向けは有り） |
| 12 | UTF-16 | Excel の「Unicode テキスト」は UTF-16LE ＋ BOM ＋ タブ | BOM と NUL の出方で判別 |
| 13 | Shift_JIS と CP932 | `①` `㈱` はしご高は CP932（Windows-31J）の拡張 | 日本語は既定で CP932 として扱う。保存で表せない文字の位置を事前に列挙 |
| 14 | 波ダッシュ・全角チルダ | 0x8160 は JIS の変換表で U+301C、CP932 で U+FF5E。全角ハイフンマイナス（U+FF0D）とマイナス記号（U+2212）も同類 | 変換表を明示し、往復で値が変わる文字を警告 |
| 15 | 文字化け・文字コードの混在 | UTF-8 を CP932 で開く・1 ファイルに複数の文字コード | 推し量りと手動の指定し直し。不正なバイト列を行と列で示す |
| 16 | 全角の数字 | `１２３`・`１，２３４`・全角空白・全角の `－` | 数として扱うかを設定できる。NFKC の正規化は明示の変換として用意し、勝手にしない |
| 17 | NUL・制御文字 | 途中の `\0`（UTF-16 の誤判別・壊れた出力） | 止めずに `␀` などで見せ、件数を報告 |
| 18 | 先頭の 0 | 郵便番号 `0123`・社員番号 `007` | 変換しない。保存は元の文字列のまま |
| 19 | 長い数字（15 桁） | Excel は有効数字 15 桁。16 桁のカード番号の末尾が 0 に、19 桁は `1.23457E+18` で桁が失われる | 文字列のまま持つ。15 桁を超える数字列に「Excel では壊れる」と警告 |
| 20 | 指数表記への誤変換 | `1E5`・`12E3`（型番） | 自動で変換しない。するなら列単位で明示 |
| 21 | 日付の曖昧さ | `01/02/03`（MDY / DMY / YMD）・`2-Mar` | 解釈しても元の文字列を保つ。曖昧なら書式の候補を示す |
| 22 | 遺伝子名の誤変換 | `SEPT2` → 2-Sep・`MARCH1` → 1-Mar・`2310009E13` → 浮動小数点・5 桁の日付シリアル値 | 「自動で変換しない」を既定にする根拠 |
| 23 | Excel 固有 | 1 行目の `sep=;`・先頭が大文字の `ID` だと SYLK と誤認・BOM なしの UTF-8 は日本語環境で CP932 として開かれる | `sep=` を方言の情報として使う（保持は選べる）。Excel 向けの書き出しで先頭の `ID` を引用符で囲む・BOM を付けるなどの対策を用意 |
| 24 | 非常に横長・巨大 | 数千〜数万列・GB 級 | 列も行も見えている部分だけ描く・流れで解析・索引。Excel の上限（1,048,576 行 × 16,384 列）を超えるなら警告 |
| 25 | 前後の空白 | `a, b`・引用符の外の空白 | 値として保ち、削るのは明示の操作 |
| 26 | 空と null | `,,` と `,"",`・`NA` `NULL` `\N` | `nullSequence` を設定でき、引用符つきの空と無しの空を往復で保つ |
| 27 | 1 ファイルに複数の表 | 空行で区切られた複数のブロック（政府系の実ファイルで最大 226 表） | ブロックの検出と分割を補助 |

**全体の原則: 読んで何も変えずに保存すると、バイト単位で同じファイルに戻る。** 引用符の付け方・改行・BOM・文字コード・末尾の改行を保つ。

## 3. セキュリティ

- **CSV（数式）インジェクション**（OWASP・CWE-1236）: セルの先頭の `=` `+` `-` `@` タブ CR が表計算で数式として解釈される。OWASP WSTG の最新版は LF と全角の `＝＋－＠` も対象に入れた（全角はロケール次第）。区切りや引用符を注入して新しいセルを作る手口もある
- OWASP の対策: 先頭に `'` を付ける・全体を引用符で囲む・`"` を二重にする。ただし Excel で保存して開き直すと無効になりうると OWASP 自身が注記。引用符の内側の先頭にタブを付ける方法は Excel で確実だがデータが変わる。無害化は出力時に行う
- エディターに勧める振る舞い:
  1. 数式を一切評価しない（表示は常に文字列）
  2. 危険な先頭文字のセルを強調し、件数を出す
  3. 「Excel 向けの安全な書き出し」を選択式で用意する（`'` を付ける・タブを付ける・変えない）。データを変えることを明示し、既定は変えない
  4. 開くときに外部のプログラムを起動しない。DDE（`=cmd|...`）の形を警告する
- その他: SYLK（先頭が `ID`）・巨大なファイルや病的な引用符による DoS（Python の旧 Sniffer は引用符の多いデータで計算量が 2 乗になり、約 1 MB の標本で 20 秒以上）→ 判別に読む量に上限を置く。閉じていない引用符でファイル末尾まで 1 セルになる場合を上限で検出して警告。不正なバイト列で落ちない

## 4. 機能と使い勝手に関わる研究

- **van den Burg, Nazábal, Sutton（2019・DMKD・CleverCSV）**: 方言の候補ごとに「行の形の一貫性」と「セルの型の一貫性」を掛けた指標で選ぶ。実データで精度 97%、乱れたファイルで既存手法より約 22% 高い。Python の Sniffer は標準的でないファイルの 36% で失敗。どの方言でも何らかの表が得られてしまうので正誤の判定が難しい、が本質。→ 試しに切ってみた結果の整合性で推し量り、上位の候補をプレビュー付きで示す
- **García（2024・Data Science）/ csv-nose**: 表の一様性で推し量り、CleverCSV や Sniffer を上回ると報告。データセットで順位が大きく変わる（CleverCSV は W3C-CSVW のコーパスで 56%）。開発者自身の評価【要確認】。DuckDB の sniffer も実用水準
- **Vitagliano ら（2023・PVLDB 16(8)・Pollock）**: RFC 4180 を基準に現実の乱れを体系的に加えた 2,290 ファイルで 16 システムの頑健さを評価。政府系ポータルで 14 の文字コード・5 の区切り・1 ファイル最大 226 表。→ **読み込みのテストにそのまま使える**
- **Python csv.Sniffer**: `has_header` は見出しの後の 21 行を見る大まかな方法で、公式も誤判定を認める。試し解析への書き直しの提案（gh-83273・PR #153694）のマージ状況は【要確認】
- **Ziemann, Eren, El-Osta（2016・Genome Biology）**: 補足資料に Excel の遺伝子リストを含む論文の 19.6%（704 本）に誤変換
- **Abeysooriya, Soria, Kasu, Ziemann（2021・PLOS Comput Biol）**: 2016 年の報告の後も増え、30.9%（3,436 / 11,117 本）。5 桁の日付シリアル値への変換も
- **Bruford ら（2020・Nature Genetics）**: HGNC が SEPT1 → SEPTIN1、MARCH1 → MARCHF1 などに改名。「道具の既定の振る舞いが利用者の世界を変えた」例
- **Microsoft**: Microsoft 365 / Excel 2024 に「自動データ変換」の設定（先頭の 0 の削除・15 桁への切り詰め・E を含む値の指数表記化を個別に無効化。日付も同様と思われる【要確認】）と CSV 読み込み時の通知。設定は利用者ごとなので、受け取った相手の Excel では変換が起きる → 「Excel で開くと壊れる値」を事前に警告する価値
- **Kandel, Paepcke, Hellerstein, Heer（2011・CHI・Wrangler）**: 直接の操作から変換の候補を推論して提案し、効果をプレビュー。意味的な型での検証・列ごとのデータ品質メーター・編集できる変換の履歴（スクリプト化）。指定の時間が短縮され、監査できる変換が使われた。後続に Profiler（AVI 2012）・商用の Trifacta。→ 列ごとの品質バー・操作履歴の再生と再利用・一括変換のプレビュー
- **OpenRefine**: ファセット・クラスタリング（キー衝突法・最近傍法による表記ゆれの統合）・操作履歴の JSON の抽出と再適用。学術的な典拠は【要確認】
- **Rahman ら（2020・SIGMOD・Benchmarking Spreadsheet Systems）**: 500 ms を対話の閾値とし、Excel・Calc・Google Sheets は公称の上限よりはるかに小さいデータで閾値を超えた（ソートは 1 万行前後、数式があると 150〜6,000 行）。検索が O(n) など、索引と増分計算が欠けている。→ 索引・見えている部分だけの描画・非同期を前提に、操作ごとに 500 ms 以内を目標に
- 未精査: DataSpread（Bendre ら・VLDB）・NOAH（PVLDB 14(6)・2021・大きな表の階層的な概観）・Panko の表計算のエラー研究
- **「CSV は標準ではない」**: Jesse Donat "Falsehoods Programmers Believe About CSVs"（2016）・Alex Gaynor "CSVs: The good, the bad, and the ugly"（2020・型が無く null と空を区別できない）。HN の要点: 不正な CSV を拒むと利用者は困り、現実の入力の多くは Excel 製 → 寛容に読み、厳密に書く
